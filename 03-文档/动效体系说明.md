# 合资金账 FundMerge · 3D 动效体系说明

> 适用版本：v5.5（含 v5.3 / v5.4 的全部内容）｜ 更新：2026-10-31 ｜ 代码位置：`assets/scene.js` + `assets/fx.js` + `assets/styles.css`（文件末尾 `v5.4 · 3D 动效体系` 与 `v5.5 · 交互反馈层` 两段）
> 读这一份就能改任何一个动效，不用再翻别处。

---

## 一、一句话

**3D 氛围用 three.js 做（背景层），空间感用 CSS 透视做（界面层），两者共用一套时长令牌与降级开关。**

为什么不是「把界面渲进 WebGL」：那样会失去文字选中、输入框、无障碍树与键盘操作，而且每次改文案都要重编译几何体。3D 只负责营造空间，界面仍然是 DOM —— 这是能同时拿到观感和可用性的唯一做法。

---

## 二、三层架构

| 层 | 技术 | 职责 | 代码位置 |
|---|---|---|---|
| **L0 三维氛围层** | three.js（WebGL） | 全站背景的线框几何体 + 粒子场，随页面切换形状与配色 | `scene.js` → `createGlobal()` |
| **L1 空间容器层** | CSS `perspective` / `preserve-3d` / `transform` | 卡片倾斜、按钮抬升、页面纵深 | `styles.css` → L1 段 |
| **L2 内容动效层** | CSS `@keyframes` | 每页专属入场族、表格行、图表、数字、提示条 | `styles.css` → L2 段 |

三层互不依赖：关掉 L0 只剩 DOM 动效，关掉 L2 只剩悬停反馈，都能单独工作。

## 三、L0：三维氛围层

### 3.1 只开一个 WebGL 上下文

```
canvas[data-scene-global]（1 个，固定在 .main 里）
  └─ WebGLRenderer（antialias:false, powerPreference:'low-power', DPR ≤ 1.5）
       ├─ Points  粒子场（桌面 190 / 触屏 90 个）
       └─ Mesh[]  线框几何体（按页面 3~6 个，来自共享几何池）
```

**关键约束：切页不重建上下文。** `setView(view)` 只做三件事——释放旧 mesh 材质、按新预设从几何池取几何体建 mesh、把透明度过渡归零重新淡入。上下文、renderer、粒子 BufferGeometry 全部复用。

> 历史教训：v5.0.1 之前是「每页一个 canvas」，切一次页要重编译着色器，实测 +20ms 主线程 + GPU 抖动；而且浏览器对同时存在的 WebGL 上下文有上限（通常 8~16 个），超出会静默丢弃最旧的，表现为「切几页后 3D 没了」。

### 3.2 每页的空间语汇

几何体形状暗示该页的内容形态，配色沿用该页语义色（浅色主题用 `dark` 那一档的饱和色，否则浅底上看不见）：

| 页面 | 几何体 | 数量 | 隐喻 |
|---|---|---|---|
| dashboard / group | icosahedron 二十面体 | 3 / 5 | 聚合、整体 |
| transactions / vouchers / logs | box 立方体 | 4~5 | 流水条目、凭单 |
| accounts / companies | cylinder 圆柱 | 3~4 | 钱柱、账户堆 |
| invoices | plane 平面 | 6 | 纸张、票据 |
| reports / group-reports | torus 圆环 | 3~4 | 周期、回路 |
| budgets / projects | octahedron 八面体 | 4 | 分配、切面 |
| debts / advances | tetrahedron 四面体 | 4~5 | 三角关系（借-还-欠） |
| categories / settings / backup | dodecahedron 十二面体 | 3~4 | 多面配置 |
| users / parties / profile | sphere 球 | 3~4 | 人 |
| 其他 / 未知 | icosahedron | 3 | 兜底 |

新增页面时在 `VIEW_SCENE` 里加一行即可，**不需要动渲染逻辑**。

### 3.3 运动参数

| 参数 | 值 | 说明 |
|---|---|---|
| 限帧 | ~24fps（`now - last < 41` 跳过） | 纯装饰，24fps 足够，省一半 GPU |
| 整组自转 | `t * 0.045` rad/帧 | 约 40 秒一圈，几乎察觉不到在转，但截图对比能看出差异 |
| 单体重旋 | `0.0011 ~ 0.0023` rad/帧 × 页面速度系数 | 慢，避免抢注意力 |
| 上下浮动 | `sin(t*0.55 + phase) * 0.16` | 呼吸感 |
| 鼠标视差 | 目标 `mouse*0.10`，缓动系数 `0.05` | 桌面端；触屏不挂监听 |
| 切换淡入 | 每帧 `mix += 0.045`（约 0.4s 到 1） | 避免几何体硬切 |

## 四、L1：空间容器与交互反馈

### 4.1 透视容器

```css
.content { perspective: 1600px; perspective-origin: 50% 22%; }
```

透视挂在滚动容器（`.content`）上，所有卡片的 `rotateX/Y` 共用同一个视点 —— 这样它们看起来是**同一空间里的一叠纸**，而不是各自为政地扭。`perspective-origin` 偏上（22%），让视线略高于页面中心，符合「俯视桌面」的直觉。

### 4.2 卡片倾斜（数值边界）

| 状态 | 位移 | 旋转 | 缩放 | 阴影 |
|---|---|---|---|---|
| 普通卡片 hover | `translateZ(26px)` + `translateY(-2px)` | `rotateX(1.1deg) rotateY(-1.4deg)` | — | 双层，最远 40px 模糊 |
| 指标卡 hover | `translateZ(32px)` + `translateY(-3px)` | `rotateX(1.4deg) rotateY(-1.1deg)` | `1.012` | 单层 44px 模糊 |
| 按下 active | `translateZ(4px)` | 无 | `0.995` | 收到 6px |

**红线（M1）：倾斜角度 ≤ 2deg，位移 ≤ 4px。** 超过 3deg 时，卡片里的数字会开始"斜着飘"，看报表会晕 —— 这是可用性问题，不是审美偏好。所以立体感主要靠 **Z 轴抬升 + 阴影**，而不是靠加大角度。

### 4.3 按钮 3D 抬升

```
默认：  无 transform
hover： translateY(-2px) translateZ(10px)
        主按钮额外 scale(1.018) + 品牌色投影 + 斜向白光扫过（0.6s 一次）
active： translateY(0) translateZ(2px) scale(.985)，时长压到 84ms
```

白光扫过用 `::after` 伪元素 + `translateX` 位移实现（不是背景渐变位移），因为前者只走合成层，不触发重绘。

### 4.4 静态立体感

卡片默认带两层阴影：

```css
box-shadow:
  inset 0 1px 0 rgba(255,255,255,.62),   /* 顶边内高光：模拟来自上方的光 */
  0 1px 2px rgba(16,24,40,.05),          /* 接触阴影：卡片压在桌面上的那条线 */
  0 2px 6px -3px rgba(16,24,40,.06);     /* 环境阴影：厚度 */
```

没有这两层，浅色主题里卡片就是一张贴纸。深色主题另有一套（白色内高光降到 `.07`，阴影换成纯黑）。

## 五、L2：每页专属入场族

八套语汇，按页面语义分配。共同边界：**位移 ≤ 22px、旋转 ≤ 4.2deg、时长 ≤ `--dur-3 × 1.15`**。

| 族 | 关键帧特征 | 用于 | 为什么是它 |
|---|---|---|---|
| **vLift** | 从下方 `+16px` 浮起，带 `rotateX(2.4deg)` | dashboard、group、group-reports | 总览是"把一盘东西托到你面前" |
| **vSlide** | 从右侧 `+22px` 推入，`rotateY(-2.6deg)` | transactions、vouchers、logs | 新条目从右边来，符合列表增长的直觉 |
| **vSlideL** | 从左侧 `-22px` 推入 | debts、advances、parties | 与流水相反的方向，形成"另一类台账"的记忆锚点 |
| **vFlip** | 绕上边缘 `rotateX(-4.2deg)` 翻下 | invoices | 票据就是纸，翻下来最贴切 |
| **vStack** | 从上方 `-14px` 落下并压平 | accounts、companies | 账户/公司是"摞起来"的对象 |
| **vZoom** | `scale(.972)` + `translateZ(-26px)` 从深处放大 | reports、budgets | 图表要有"数据浮出水面"的感觉 |
| **vUnfold** | `scaleY(.988)` 自上而下展开 | settings、categories | 设置分组是逐条展开的 |
| **vDrift** | 斜向 `8px/10px` 轻飘，最弱 | users、profile、backup、projects | 辅助页不需要强调 |

### 5.1 交错节奏

同一页内最多 6 个区块参与，间隔 **18ms**（比旧的 24ms 更紧）：

```
第1个 0ms → 第2个 18ms → 第3个 34ms → 第4个 48ms → 第5个 60ms → 第6+个 70ms
```

间隔变小是因为不同族的位移方向不同，间隔太大反而显得"一片一片地弹"。

### 5.2 次级动效

| 元素 | 动效 | 说明 |
|---|---|---|
| 指标数字 `.stat-value` | `numLift`：淡入 + 上浮 3px | 配合已有的数字滚动 |
| 表格行（流水/凭证） | `rowInR`：从右滑入 10px | 只前 8 行，再多是纯负担 |
| 图表 `.chart svg` / `.cf-table` | `chartBloom`：`scale(.985)` + `translateZ(-8px)` | 从中心散开 |
| 提示条 `.alert` | `alertSlide`：左侧抽出 + 横向拉伸 | 比淡入更像"来了一条新消息" |
| 弹窗 `.modal` | `modalIn3D`：`translate3d(0,14px,-60px) rotateX(1.6deg)` | 从屏幕深处浮到眼前 |

## 六、性能策略

| 措施 | 实现 | 收益 |
|---|---|---|
| 单上下文 | 全局层固定 1 个，内嵌层（hero/auth）各 1 个，实测峰值 **2 个** | 避免上下文上限与着色器重编译 |
| 几何体池 | 9 种几何体模块加载时建好，切页只换 mesh 引用 | 切页零编译 |
| 限帧 | 24fps（41ms 跳帧） | GPU 占用减半，肉眼无差 |
| DPR 封顶 | `min(devicePixelRatio, 1.5)` | 4K 屏上像素量降到 56% |
| 关抗锯齿 | `antialias: false` | 纯线框装饰层看不出差别 |
| 页面不可见暂停 | `visibilitychange` → 停 RAF | 切到别的窗口不烧电 |
| 视口外暂停 | 内嵌层用 `IntersectionObserver` | 滚动出屏不渲染 |
| 事件节流 | 鼠标视差用 `passive: true` | 不阻塞滚动 |
| CSS 合成层 | `will-change: transform` 只在 hover 规则内声明 | 不常驻占用合成层 |

实测（1440×1000，Windows）：

| 指标 | 结果 |
|---|---|
| WebGL 上下文数 | 2（全局 1 + hero 1） |
| 连续切页 12 次后上下文数 | 仍为 2，无增长 |
| 连续切页 12 次耗时 | ~190ms（含渲染，平均每页 ~16ms） |
| 主线程 rAF 帧率 | 166fps（说明 3D 渲染没有拖住主线程） |

## 七、降级矩阵

四种条件，任一命中就退回低一档，**不会出现白屏或半残状态**：

| 条件 | 触发方式 | L0 三维层 | L1 倾斜 | L2 入场 |
|---|---|---|---|---|
| 正常 | — | 开启（opacity .78 / 深色 .55） | 开启 | 按页族 |
| 流畅模式 | 设置页 → 性能档位「流畅」(`data-perf="low"`) | **不建上下文**，canvas 隐藏 | 关闭 | 关闭 |
| 动效关闭 | 设置页 → 动效开关 (`data-motion="off"`) | **不建上下文** | 关闭 | 时钟压到 0.001ms |
| 系统减弱动效 | 操作系统 `prefers-reduced-motion: reduce` | **不建上下文** | 关闭 | 时钟压到 0.001ms |
| 窄屏 / 触屏 | `max-width: 820px` 或 `pointer: coarse` | 开启（粒子减半、几何体少 1 个） | **关闭**（保留 active 缩放） | 位移族改纯淡入 |
| WebGL 不可用 | 创建失败 / 上下文丢失 | 静默降级，`data-scene-ready` 不设置，画布保持全透明 | 正常 | 正常 |

> 触屏为什么要关倾斜：触屏没有 hover 状态，`:hover` 会在 tap 后残留，表现为"点一下卡片就歪着不回来了"。这是移动端最典型的动效事故。

## 八、扩展指引

### 8.1 新增一个页面

1. `views.js` 里写 `viewXxx()`
2. `app.js` 的 `VIEW_META` / `renderView` 的 switch 里加分支
3. `scene.js` 的 `VIEW_SCENE` 里加一行：`xxx: { geo:'octa', n:4, spread:4.4, speed:0.85, light:…, dark:…, dots:150 }`
4. `styles.css` 的族映射里，把 `[data-view="xxx"]` 归到八族之一
5. 完事 —— 不需要写任何新的 keyframes

### 8.2 调整整体动效速度

设置页的三档档位改的是 `--motion-scale`（0.6 / 1 / 1.4），所有 `--dur-*` 都乘了它，所以**一处改、全站变**。

### 8.3 加一个新动效族

在 `styles.css` L2 段：
1. 写 `@keyframes vXxx { from {...} to { opacity:1; transform:none } }`
2. 在族映射里加 `[data-view="…"].is-entering > * { animation-name: vXxx }`
3. 边界仍然遵守：位移 ≤ 22px、旋转 ≤ 4.2deg

## 九、雷区清单（踩过的）

| # | 雷 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | 对同一个 canvas 重建 WebGL 上下文 | 切主题 / 切性能档位后 3D 层消失，控制台无报错 | `dispose()` 时 `forceContextLoss()`，重建前**换一块新 canvas** |
| 2 | 每页新建上下文 | 切几页后 3D 没了（浏览器丢弃最旧上下文） | 全局层只建 1 个，切页只换参数 |
| 3 | 浅色主题沿用浅色线框 | 3D 层"看不见"，以为没渲染 | 浅色主题用饱和色 + 更高不透明度 |
| 4 | `will-change` 写在基础选择器 | 每张卡长期占一个合成层，滚动更卡 | 只在 hover 规则内声明 |
| 5 | 给含 canvas 的元素做位移动画 | 画布被拖进合成层逐帧重绘，掉帧 | 只淡入不位移（`.stat.hero` 走 `viewEnterFade`） |
| 6 | 触屏保留 hover 倾斜 | 点一下卡片歪着不回位 | 包在 `@media (hover:hover) and (pointer:fine)` 里 |
| 7 | 动效开关只认系统偏好 | 设置里关掉动效，3D 还在转，开关像坏的 | `reduceMotion()` 同时读 `data-motion="off"` |
| 8 | 倾斜角度给到 5deg 以上 | 数字看着"斜飘"，看报表头晕 | 上限 2deg，靠 Z 轴和阴影做纵深 |

# 附：v5.5 增量 —— 深色可见性、指针反馈与粒子

> 这一节只写 v5.5 新增/修改的部分。上面九节仍然有效，两处被改动的地方已在条目里标注。

## 十一、为什么深色模式下"动了看不出来"

v5.4 的立体感只有一条线索：**黑色投影**。同一套 `0 18px 40px rgba(16,24,40,.26)` 放在 `#0b1220` 上等于没有——投影和被投影的背景一样黑。表现就是：hover 了、鼠标也变了、但卡片"没动"。

v5.5 把"高度"拆成两条物理线索，按主题各给一套权重：

| 线索 | 语义 | 浅色主题 | 深色主题 |
|---|---|---|---|
| 投影 | 这件东西离开了桌面 | 主用（`--elev-lift`） | 弱用（只保留底部暗影，`rgba(0,0,0,.72)`） |
| 外发光 | 这件东西亮了 | 轻用 | **主用**（品牌色 46% 光晕 + 1px 品牌色圆环） |
| 顶沿内高光 | 上方来光，纸有厚度 | `.62` 白 | `.11` 白（原 `.07` 在 `#111a2b` 上不可见） |

落地方式：全部走令牌 `--elev-lift` / `--elev-lift-strong` / `--elev-rim`，规则里不再写死 `rgba` 投影；深色只在 `[data-theme="dark"]` 段覆盖令牌值。

### 11.1 三个具体改动

1. **静态卡片**顶沿内高光 `.07 → .11`，并且必须带 `html` 前缀（`html[data-theme="dark"] .card`）。v5.4 原来那条就是 `html[data-theme="dark"] .card`，少写 `html` 会因特异性低一级而**静默失效**——这条已经踩过，写在雷区第 9 条。
2. **hover** 深色下改为 `--elev-lift`（含品牌色外发光与 1px 亮环），浅色仍用中性投影。
3. **按钮** 深色下加 `0 0 22px -8px` 品牌微光，否则 `translateY(-2px)` 在深底上看不出位移。

### 11.2 3D 背景同步提亮（scene.js）

| 参数 | v5.4 | v5.5 | 原因 |
|---|---|---|---|
| 深色线框不透明度 | `.16 + .045i` | `.26 + .055i` | `.16` 在 `#0b1220` 上几乎融进背景 |
| 浅色线框不透明度 | `.30 + .07i` | `.32 + .07i` | 略提，配合更高的粒子密度 |
| 深色粒子不透明度 | `.34` | `.52` | 同上 |
| 深色粒子混合 | Normal | **Additive** | 重叠处自然变亮，等同"发光"，不需要后处理 |
| 粒子层数 | 1 层（190 个） | **2 层**（远 190 / 近 61） | 有远近才有纵深；单层读起来像屏幕脏点 |
| 指针视差系数 | `0.10 / 0.07` | `0.16 / 0.11` | 余光里能感觉到场景在跟着动，又不和滚动打架 |

> 第 3 条雷区（"浅色主题沿用浅色线框"）的镜像问题：深色主题沿用深色主题的低不透明度，同样等于看不见。改数值时**两个主题都要看一眼**。

## 十二、指针反馈层（`assets/fx.js`）

### 12.1 三层 DOM

| 层 | 元素 | z-index | 干什么 | 为什么在这个层级 |
|---|---|---|---|---|
| 环境粒子 | `canvas.fx-field` | 2 | 漂浮光点 + 近邻连线 + 指针聚散 | 在内容之上（1）、侧栏（3）之下：卡片不透明，放内容下面等于只剩页边缝能看见 |
| 指针光斑 | `div.fx-aura` | 4 | 跟随光标的柔和径向光 | 在内容之上、顶栏（25）之下，不遮操作 |
| 点击迸发 | `canvas.fx-burst` | 90 | 按下时迸出 13 个粒子，0.6s 消散 | 要到顶栏之上才看得见，但仍低于弹窗（120） |

三者都 `pointer-events:none`，不拦截任何点击。

### 12.2 卡片追光：为什么用 background-image 而不是伪元素

`.card::before`（顶部 1px 高光）和 `.stat::after`（v4.7 的装饰圆斑）都已被占用，再加伪元素会和既有视觉打架。改用 `background-image` 叠一层径向渐变：

```css
.card, .stat:not(.hero), .co-card, .plan-card {
  background-image: radial-gradient(300px circle at var(--fx-mx, -400px) var(--fx-my, -400px),
    var(--fx-spot), transparent 64%);
}
```

- 默认中心放在 `-400px`（视口外），未 hover 时完全不可见，不增加待机亮度。
- **必须用 `:not(.hero)` 排除品牌渐变卡**：`.stat.hero` 的底座是 `background` 简写（linear-gradient），任何后置的 `background-image` 都会把渐变整条覆盖掉，深色下会变成"白底白字"。这条踩过一次，见雷区第 10 条。
- JS 只在 `pointermove` 时写 `--fx-mx/--fx-my`（rAF 节流），不触发重排。

### 12.3 倾斜：固定角 + 动态角

```css
.card.hover:hover {
  transform: translate3d(0,-2px,26px)
             rotateX(calc(.6deg + var(--fx-rx, 0deg)))
             rotateY(calc(-.7deg + var(--fx-ry, 0deg)));
}
```

固定角从 `1.1/-1.4deg` 降到 `.6/-.7deg`，把余量留给 JS 的 ±1.2deg：**相加后仍 ≤ 2deg**（M1 铁律不变）。效果从"整块翻一下"变成"跟着手走"。

### 12.4 按钮磁吸

`--fx-tx / --fx-ty` 由 JS 按指针相对按钮中心的偏移写入，最大 ±2.2px，直接拼进 hover 的 `translate3d`。数值刻意很小：再大就会觉得按钮在躲鼠标。

### 12.5 粒子系统参数

| 项 | 值 | 说明 |
|---|---|---|
| 数量 | `clamp(34, 视口面积/26000, 78)`，1080p 约 64 | 按面积给密度，小屏不噪 |
| 吸引半径 | `clamp(120, 屏宽×0.14, 200)` | 大屏不出现"什么都没有" |
| 斥力半径 | 34px | 防止粒子堆成一个点 |
| 连线距离 | 92px，透明度 `(1-d²/L²)×0.22` | 超过 92px 就是一团乱麻 |
| 帧率 | 跟随 rAF，dt 上限 50ms | 切后台回来不会"炸开" |
| 点击迸发 | 13 个，速度 70–260 px/s，重力 220 px/s² | 0.6s 内消散 |

粒子颜色不是写死在 JS 里的：从 `--fx-dot / --fx-link / --fx-burst-*` 读取（根与深色各一套），并在 `data-theme` 变化时重读。这样"深色下粒子更亮"只是一条 CSS 令牌，不用改代码。

## 十四、v5.5 新增雷区

| # | 雷 | 现象 | 正确做法 |
|---|---|---|---|
| 9 | 深色覆盖规则少写 `html` 前缀 | 新规则"写了不生效"，计算值还是旧的 | 原规则是 `html[data-theme="dark"] .card`，覆盖也必须带 `html` |
| 10 | 用 `background-image:none` 排除渐变卡 | hero 卡渐变被抹掉，浅色主题下白底白字 | 用 `:not(.hero)` 从源头排除，不要"先覆盖再置空" |
| 11 | 在 SVG 元素上用 `transform: scale()` 做呼吸 | 圆会沿用户坐标原点放大，看起来"飘走" | 加 `transform-box: fill-box; transform-origin: center` |
| 12 | `.fb-svg` 只写 `width:100%` | 单列布局时整图放大 1.5 倍，节点和字号一起变巨 | 加 `max-width` 并居中；手机端给 `min-width` + 横向滚动 |
| 13 | 看板每 5 秒无条件 `innerHTML` | 悬停中的丝带每 5 秒闪一下，滚动位置丢失 | 先比数据签名，变了才替换；替换后闪一次底色 |
| 14 | 暂停只改 UI 不读回偏好 | 重启后"暂停"失效 | 偏好存 `fm-fb-live`，启动时写回 `UI.fbLive` |
