## 一、这是什么

**合资金账 FundMerge** 是面向中小企业（主要在加纳）的 **Windows 桌面资金管理软件**。

| 特征 | 说明 |
|---|---|
| 运行形态 | Electron 45 打包的单个 exe 安装包，装完即用 |
| 离线 | **完全离线**。无 CDN、无字体外链、无自动更新。实测阻断全部 http(s) 后功能正常 |
| 多公司 | 一个账号管多家公司，账本完全隔离；另有集团合并视图 |
| 集团模型 | 总公司持资金，可拨款、可代子公司付款 |
| 数据 | 默认在 `<安装目录>\data`；另有账套包 `.flpack` 作为交付/迁移单位 |
| 交付物 | 安装包 + 四份文档（操作手册、交接说明、需求解读、打包发布说明） |

**核心设计取向**：数据在用户手里（可进文件夹看、可整目录复制、可导出单一账套包）；不引入网络依赖；不做"看起来能用实际不安全"的功能。

## 二、技术栈

| 层 | 技术 | 备注 |
|---|---|---|
| 桌面壳 | Electron 45（Chromium 140 / Node 20+） | `contextIsolation: true`、`sandbox: true`、packaged 版关闭 devTools |
| 渲染层 | **原生 HTML/CSS/JS，无框架、无构建** | `file://` 不支持 ES module，五个脚本按顺序加载 |
| 图表 | 手写 SVG 字符串 | 不引图表库（离线硬要求） |
| 3D | three.js r152 UMD（本地 619KB） | 仅装饰；弹窗打开时暂停渲染 |
| 存储 | 桌面：JSON 文件 + 附件目录；网页：localStorage + IndexedDB | |
| 密码 | PBKDF2-SHA256 + 16 字节随机盐（WebCrypto） | |
| 账套包 | 自研 STORE 模式 ZIP + 可选 AES-256-GCM | 产物是真 ZIP，可用 7-Zip 打开 |
| 云盘凭据 | Electron `safeStorage`（绑定 Windows 账户） | 存 `%APPDATA%\FundLedger\backup.json` |

**脚本加载顺序**（`index.html`，不可打乱）：

```
core.js → ui.js → views.js → modals.js → vendor/three.min.js → scene.js → app.js
```

## 四、构建与发布

```bash
npm install
node node_modules/electron-builder/cli.js --win --x64 --config.directories.output=dist
```

产物：`dist/FundMerge-Setup-<ver>.exe`（约 116MB）+ `dist/win-unpacked/`。

### 4.1 构建必踩的坑

1. **先结束 `合资金账.exe` 进程**，否则解包阶段 EBUSY。
2. **输出目录不能有 `win-unpacked.tmp` 残留**。某些环境的 safe-delete 垫片会把 `fs.rm` 转成"回收站"，大目录 trash 失败 → 报 `[safe-delete] 操作失败`。规避：换新的输出目录名。
3. **不要用 `mv dist dist_old` 替换产物**，文件系统视图延迟时会误删产物。直接 `cp` 安装包。
4. **electron-builder 的 `build.productName` 与 `build.win.artifactName` 会覆盖顶层同名配置**。只改顶层不生效——v4.0.0 踩过，出来的还是旧名字。
5. 未配置代码签名证书 → 安装时出现 SmartScreen「未知发布者」，属正常。

### 4.2 发版门禁（必须跑）

```bash
sh deliverables/pack-gate.sh --self-test   # 验尺子：6 例自检
sh deliverables/pack-gate.sh dist          # 验产物：结构/凭据/版本一致性
```

退出码 0 才允许发布。**注意**：`node pack-scan.js dist | tail` 的退出码是 `tail` 的（恒 0），必须用包装器。

门禁查三类：A 结构断言（禁止 `data/`、`*.bak.json`、`debug.log`、开发文档）、B 文本扫描（明文凭据、手机号、本机路径）、C 版本一致性（asar 版本必须等于 exe 版本）。

> **门禁是"自证型"**：执行者与被验证者是同一个人。它能防无意改动与夹带，**不防有意绕过**。真正防恶意需要 CI 从干净 checkout 运行。

### 5.1 `cf` 字段（现金流量项目）

决定该分类归到现金流量表哪一行：`none` / `op_in_sales` / `op_in_other` / `op_out_purchase` / `op_out_salary` / `op_out_tax` / `op_out_other` / `inv_*` / `fin_*`。`none` = 不计入。

### 5.2 代理属性（重要）

`DB.accounts` / `DB.transactions` / `DB.categories` 等是 **`attachCompanyProxy()` 挂的代理属性**（`enumerable: false`），指向当前 `COMPANY`。这是 v3.0.0 为了让 v2 视图代码零改动而做的兼容层。

**新代码请优先用 `COMPANY.xxx`，或给函数传 `co` 参数。不要依赖代理做新逻辑。**

## 六、核心业务规则（改动前必读）

### 6.1 余额

```
账户余额 = 期初余额 + 收入 − 支出 − 转出 + 转入
```

`balanceOf(acc, upto, co)` 支持按日期截断。

### 6.2 不进统计的流水

- 内部转账（同公司账户互转）
- 公司间转账（`peerCompanyId` 存在）
- 集团代付的子公司侧记录（`noCash: true`）
- 分类 `cf === 'none'` 的流水（如余额调整）

### 6.3 集团总公司（`isParent`）

全集团唯一。勾选新的会自动取消旧的。作用：持资金、可拨款、可代付。

### 6.4 集团代付

子公司记账时选「总公司账户」付款 → 子公司流水 `accountId: ''`、`noCash: true`、`fundedBy`；
`syncGroupMirror()` 在总公司账上生成镜像（分类「对子公司代付」、`mirrorOf` 指向源流水）。

- 子公司余额**不变**，总公司余额**减少**
- 集团总额只减少一次
- 编辑/删除时用 `syncGroupMirror` / `removeLinkedTx` 维护镜像

### 6.5 公司间转账

一次生成两条：转出方 `direction:'out'`、转入方 `direction:'in'`，共享 `pairId`。
双方 `cf` 均为 none，不影响收支统计；集团总额不变。**不支持直接编辑**，删除时连带删除配对。

### 6.6 总公司登记方式（`parentMode`）

- `company`（默认）：总公司作为独立公司参与合并
- `registry`：仅作集团登记主体，不参与合并计算
- `accountingCompanies()` 统一过滤，`groupTotals()` 已按此口径

### 6.7 附件归档

```
<数据目录>/files/<公司ID>/<YYYY-MM>/<YYYYMMDD-HHmmss>_<名称>.<ext>
```

元数据只存 `relPath`（相对数据目录，正斜杠）。所有文件 IPC 用 `path.resolve` 前缀校验防目录穿越。

### 6.8 其它硬规则

- 有流水的账户不能删，只能停用；被使用的分类同理
- 对账差异通过「余额调整」分类的流水实现，不改期初余额
- 往来结清自动生成对应流水
- 金额 2 位小数、千分位；**流入红、流出绿**（国内习惯）
- 导出 JSON 不能带 BOM；BOM 只加给 CSV
- 破坏性操作必须 `requireCode: true`（随机 4 位数字）

### 6.9 云盘备份版本池（v4.9）

- 备份对象 = 完整账套包 `.flpack`
- 手动 + 自动**统一池**，上限 **7 个**，超限删最旧（云端 DELETE + 索引移除）
- 索引存 `%APPDATA%\FundLedger\backup-index.json`，云盘不可用也能查历史

### 13.1 动效卡顿：四个根因与对应改法

| # | 根因 | 位置 | 改法 |

### 13.2 新增「界面流畅度」三档

- `perfMode()` 读 `localStorage['fm-perf']`：`auto` / `smooth` / `rich`
- `detectGpu()` 在 boot 时通过 IPC `sys:gpu` 问主进程要 `app.getGPUFeatureStatus()`，把结果写进 `documentElement.dataset.gpu`（`hw` / `soft`）
- `applyPerf()` 据此设置 `data-perf="low|high"`
- CSS 侧 `html[data-perf="low"]` 关闭：装饰光晕、3D 画布、入场与行动画、悬停位移与阴影、按钮缩放、弹窗回弹、环形图放大、侧边栏过渡

**新增 IPC**：`ipcMain.handle('sys:gpu')` → `{ ok, compositing, hardware, rasterization, webgl, softwareRender }`；preload 暴露 `window.desktop.gpu()`。

⚠️ 注意：`app.getGPUFeatureStatus()` 在**窗口创建前**会返回 `disabled_software`（GPU 进程尚未初始化）。必须在窗口 ready 之后取，否则会误判成「没有显卡」而全量降级。实测同一进程：启动时 `gpu_compositing: disabled_software` → 窗口就绪后 `enabled`。

### 13.4 踩过的坑（v5.0.1 新增）

1. **`position: absolute` 的装饰元素会撑出横向滚动条**：把 fixed 改成 absolute 后，`right: -180px; width: 680px` 让页面多出 168px 横向滚动，兼容性用例（I03）三个宽度全部失败。装饰性溢出必须用背景图或 `overflow: clip`，不能用定位硬怼。
2. **`app.getGPUFeatureStatus()` 有时序**：见 13.2 的警告，窗口就绪前后结果相反。
3. **3D 上下文可以复用**：`canvas` 被 `innerHTML` 替换后虽然脱离了文档，WebGL 上下文仍然有效，`replaceChild` 塞回去就能继续用，不必重建。
4. **测试期望要跟着口径走**：G23 一开始断言「registry 模式下合计为 0」，实际应是「只并分公司、不含总公司」。写断言前先把口径推一遍。

## 十四、v5.0.1 修订（2026-10-29）—— 视觉与动效升级

### 14.1 动效令牌（`assets/styles.css` 顶部）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--ease-standard` | `cubic-bezier(.22,1,.36,1)` | 元素**出现**：弹窗、页面、浮层、表格行 |
| `--ease-exit` | `cubic-bezier(.4,0,1,1)` | 元素**消失**：退场用加速曲线 |
| `--ease-move` | `cubic-bezier(.4,0,.2,1)` | **原地**变化：hover、focus、折叠、主题 |
| `--dur-0..4` | 90 / 120 / 200 / 260 / 320ms | 均乘 `var(--motion-scale)`，设置页三档继续有效 |
| `--dur-shake` | 320ms | 校验抖动专用，不与 `--dur-4` 共用 |

`--ease` / `--ease-soft` 是**兼容别名**（26 处旧引用），删除会让这些 `transition` 简写整条失效、全站静默停动，不得清理。`--dur-4` 与 `--ease-exit` 当前无消费者，为下钻与弹窗退场预留，同样不得按"死令牌"删除。

曲线原则：**入场用减速、退场用加速、hover 用对称**。三者混用是"廉价感"的主要来源——入场若用对称曲线会显得拖沓，hover 若用减速曲线回程会拖。

节奏调整：页面切换 stagger 由 `0/40/75/105/130/150` 改为 `0/24/44/60/72/80`；表格行入场由前 8 行 200ms 收到前 6 行 180ms；弹窗由 `translateY(10px) scale(.975)` 改为 `translate3d(0,8px,0) scale(.98)`；5 处 `animation-fill-mode: both` 改为 `backwards`（`both` 的 forwards 段会冻结终态、挡住后续 class 下发的 transform，属可维护性问题，不是性能问题）。

### 14.2 一并修掉的显示缺陷

1. `tr:hover td { background:#fafbfd }` 以不透明底覆盖了 tr 级品牌色 hover——`td` 背景绘制在 `tr` 之上，25 张表的品牌 hover 从未生效。已删除该行，只保留 `tr` 上色。
2. `.stat:hover` 未限定 `.is-clickable`，4 张不可点击的指标卡在"假装可点"。已改为仅可点击卡抬升。
3. 深色主题对比度：`.auth-err`（登录失败唯一反馈）、`.pill` 四色、`.alert` 三态、`.import-errors`、`.cf-total` 共 9 处。**修法只加 `[data-theme="dark"]` 覆盖，浅色主题字色一字未动**——浅色下这些值本已达标，改语义令牌反而会让 `.pill.ok` 从 4.6:1 掉到 3.6:1。
4. 文本框的 `outline:none` 特异性高于全局 `:focus-visible`，键盘 Tab 到录入框无任何可见焦点。已补 2px 实线单环（`outline-offset:0` + 压掉装饰光晕），错误态环跟随 `--danger`。

### 14.3 键盘与读屏（`app.js` / `ui.js` / `index.html`）

- `enhanceA11y()` 在每次重绘后给**非原生控件**上的 `[data-action]` 补 `tabindex="0"` 与 `role="button"`，并给 `thead th` 补 `scope="col"`、当前导航项补 `aria-current="page"`。此前指标下钻与进入公司账本对键盘用户完全不可达。

## 十九、v5.2.0：数据完整性收口（2026-10-30）

> 说明：这批改动原按 v5.1.0 推进，发布前确定最终版本号为 **v5.2.0**，代码与文档已统一改为 5.2.0。

### 19.1 孤儿流水不再按 1:1 折算（核心修复）

## 二十、v5.3.0：票据资金流转（2026-10-31）

### 20.1 口径（一句话）
钱在「登记票据」时从现金/公户挪进「票据未回资金」，此后再怎么流转账面资金都不变；只有「报账」把它记成费用，账面资金才真正减少。

账面资金 = 现金 + 银行 + 票据未回 + 未报账 + 借支备用金 + 借出款。
**借入款、员工未报销不进账面资金**（应付款项，对账单下方单列）。

### 20.2 两个内置系统账户
- 类型：`bill_pending`（票据未回资金）/ `unreported`（未报账资金）；固定 id `sys-bill-pending` / `sys-unreported`。
- `ensureSystemAccounts(co, base)` 幂等创建（`newCompany` 与 `normalizeCompany` 各调一次），币种跟随本位币。
- `isSystemAcc()` 判定；账户页置顶并标「系统账户」；后端三处守卫：编辑 / 删除 / 对账调整全拒绝。
- 手记流水的账户下拉（`openTxModal`）与转账目标（`otherCos`）都排除系统账户。

### 20.3 票据字段（新增）
`accountId`（付款账户）、`expenseCategoryId`（报账费用分类）、`form`（`unreported`/`reported`）、`reportedAt`/`reportedBy`、`txIds[]`、`migrated`。

### 20.4 分录（core.js，纯函数便于测试）
| 事件 | 函数 | 流水 | 总额 |
|---|---|---|---|
| 登记 | `postInvoice(inv,'register')` | `transfer` 付款账户 → 票据未回，A | 不变 |
| 整张回完 | `postInvoice(inv,'receive-done')` | `transfer` 票据未回 → 未报账，A | 不变 |
| 报账 | `reportInvoice(inv,cat)` | `out` 从未报账账户，A，分类=cat | **−A** |
| 撤销报账 | `unreportInvoice(inv)` | 删除报账那笔 out | **+A** |
| 删除票据 | `removeInvoicePostings(inv)` | 删除该票全部流水 | 回到登记前 |

- **登记永远先进票据未回**（即使状态是已回），再由 `receive-done` 转入未报账。原因：若 register 按状态分流，编辑重发流水时「status=done 就补发 receive-done」会重复扣减。
- **撤销报账用删除而非冲销**：冲销会留「支出A+收入A」，净额对但分类支出统计虚高 A。
- `postInvoice` 拒绝 `form==='reported'` 的票据，防调用方重复记账。

### 20.5 计算层
- `companyTotals` / `groupTotals` 新增 `billPending` / `unreported` 两个字段；**`bank` 改为按 `type==='bank'` 求和**（原 `total - cash` 会把系统账户算进银行存款）。
- `invoiceFund(co)` 返回两个桶的当前余额（`balanceOf` + 汇率折算）。
- 资金对账单：6 项构成 + 「应付款项（不计入）」独立卡片；导出 CSV 同步。
- 现金流量表**无需改动**：期初/期末用 `totalBalance()`（含票据桶），期间净额只统计 `in/out`（transfer 跳过），两者天然对齐。

### 20.6 UI
| 位置 | 改动 |
|---|---|
| 记一笔（支出） | 新增「票据状态」下拉（不用/未回/部分回/已回）；选中后分类标签变「报账费用分类（可留空）」；选票据时不生成普通支出，改为内部转账 |
| 票据页 | 新增「形态」列与四张统计卡（票据未回资金/未报账资金/已报账/逾期）；行内「回票 / 报账 / 撤销报账」；已报账行禁用编辑删除 |
| 票据弹窗 | 新增付款账户、报账费用分类；状态只读（由回票推进）；金额或账户变更时重发流水 |
| 报账弹窗 | 选费用分类 + 报账日期，二次确认（随机码） |
| 撤销报账 | 二次确认，跨月额外提示，写操作日志 |
| 账户页 | 系统账户置顶 + 标记 + 禁编辑/删除/对账 |
| 资金流水 | 自动流水带「票据·付款待票 / 回票转入 / 报账」标签 |

### 20.7 期初迁移
`migrateInvoices(co, base)` 在 `normalize()` 末尾执行：未回/部分回 → 票据未回账户全额 A；已回未报账 → 未报账账户全额 A；已报账的不进桶。每张票打 `migrated`，只迁一次。
> 部分回票据按**全额 A** 入桶（不是 A−R），与旧对账单口径差 ΣR，迁移后账面资金会略增——这是「整张未回」口径的必然结果。

### 20.8 验证
Electron 断言 15 项全过：T1–T5（登记/部分回/回票/报账/撤销的余额与总额）、E2E 5 项（界面提交全链路）、页面渲染 8 项（账户页系统账户、票据页形态列、对账单六项、记一笔票据下拉与账户排除、三角色 × 20 页）。

### 21.5 三个必修的坑（已验证）
1. **同一 canvas 不能重建 WebGL 上下文**：`dispose()` 里 `forceContextLoss()` 后，必须换一块新 canvas 才能再建。否则「切主题 / 切性能档位后 3D 层消失」，且控制台无报错。已在 `mountGlobal()` 用 `dataset.used` 标记处理。

### 22.2 深色可见性：根因与修法

**根因**：v5.4 的"浮起"只有黑色投影一条线索。`rgba(16,24,40,.26)` 落在 `#0b1220` 上与背景同色，hover 只剩 1° 倾斜，用户感知为"没反应"。

**修法**：把高度拆成两条线索，按主题分配权重。

| 令牌 | 浅色 | 深色 |
|---|---|---|
| `--elev-lift` | 中性投影 | 黑色底影 + 品牌色 46% 光晕 + 1px 亮环 |
| `--elev-lift-strong` | 更深的投影 | 同上，光晕加到 54% |
| `--elev-rim` | 品牌 26% | 品牌 56% |
| `--fx-spot`（卡片追光） | 品牌 12% | 品牌 30% |
| 静态顶沿内高光 | 白 `.62` | 白 `.11`（原 `.07`） |

规则里不再写死 `rgba` 投影；`scene.js` 的深色线框 `.16 → .26`、粒子 `.34 → .52` 且改 `AdditiveBlending`。

**踩坑**：新加的 `[data-theme="dark"] .card` 一度不生效——v5.4 原规则写的是 `html[data-theme="dark"] .card`，特异性高一级。深色覆盖必须带 `html` 前缀。已记入动效文档雷区第 9 条。

## 二十六、v5.5.5 弹窗关闭修复 + 数据计算逻辑补全（2026-10-31）

### 26.1 弹窗关闭缺陷（DEF-F）

**现象**：部分页面点「确认 / 保存」后弹窗不自动关闭。

**根因**：`closeModal()` 是异步的（240ms 退场动画）+ 幂等保护（`if (entry.closing) return`）。`onConfirm` 回调通常是 `() => { closeModal(); commit(); }`——第一次 `closeModal()` 关确认框（异步，标记 closing=true），`commit()` 里的第二次 `closeModal()` 撞上 `entry.closing` 被幂等拦截，底层表单就没被关闭，240ms 后确认框退场、底层表单重新显示。

**修复**：
1. `ui.js` 新增 `closeModalNow()`：同步 `finalizeClose` 当前栈顶（无动画、不走幂等保护）。
2. `app.js` `confirm-ok`：先 `closeModalNow()` 摘掉确认框，再执行 `onConfirm`——这样回调里的 `closeModal()` 就能正常关到底层表单。
3. `ui.js` `requireAdminPassword` 的 `closeModal()` 同样改为 `closeModalNow()`。

**验证**：新增弹窗关闭专项（9 项全 PASS：新建账户、编辑账户、记一笔、编辑流水、删除流水、编辑往来款、删除往来款、公司档案编辑，均确认/保存后关闭）；回归 215 项全 PASS，无回归。

## 二十七、v5.5.5 账套导入 bug 定位与修复（2026-11-01）

### 27.1 现象

用 V5.2.0 导出的账套文件（.flpack 账套包），在 V5.5.5 导入时提示「导入成功」，但导入后查看账户、流水、期初余额、往来单位等，仍是导入前的旧数据。

### 27.2 根因（导入覆盖逻辑，非版本兼容 / 字段映射 / 事务回滚）

问题出在**账套包导入（flpack）与云盘恢复**这两条「主进程直接写盘」的路径，渲染层多调了一次 `saveDB()`：

| 步骤 | 动作 | 结果 |
|---|---|---|
| 1 | `window.desktop.flpack.import()` → 主进程 `flpack.applyImport()` | 把 V5.2.0 账套数据写到磁盘 `data.json`（正确，且带回滚保护） |
| 2 | 渲染层 onConfirm 里 `saveDB()` | **把「导入前的旧内存 DB」写回 `data.json`，覆盖了刚导入的数据** ← 根因 |
| 3 | `location.reload()` → `loadDB()` | 从磁盘读到的还是旧数据 |

对比 JSON 导入（`applyImport`）：它是**先 `DB = next` 替换内存，再 `saveDB()`**，所以保存的是新数据，无此 bug。

受影响的两处：
- `assets/modals.js` `importPack` 的 onConfirm（第 2642 行 `saveDB()`）
- `assets/app.js` `cloud-restore` 的 onConfirm（第 2170 行 `saveDB()`）

### 27.3 修复

去掉这两处 onConfirm 里多余的 `saveDB()`（以及随之无意义的 `logAction`，因为 reload 会丢弃旧内存 DB）。主进程已写盘，直接 `location.reload()` 让 `loadDB()` 重新读新数据即可。

```js
// 修复前（错误）
const res = await window.desktop.flpack.import({ path, password });
if (!res.ok) return toast('导入失败：' + res.error, 'err');
logAction('导入', {...});
saveDB();            // ← 把旧内存覆盖掉刚导入的数据
toast('导入成功，正在重新加载…', 'ok');
setTimeout(() => location.reload(), 900);

// 修复后（正确）
const res = await window.desktop.flpack.import({ path, password });
if (!res.ok) return toast('导入失败：' + res.error, 'err');
toast('导入成功，正在重新加载…', 'ok');
setTimeout(() => location.reload(), 900);
```

### 27.4 验证

- 用真实 `flpack.pack` 打包一份 V5.2.0 数据 → `flpack.applyImport` 导入到临时目录，磁盘公司名变为「V5.2导入公司」（正确）。
- 模拟修复前 `saveDB(旧内存)`：磁盘公司名被覆盖回「旧数据公司」（复现 bug）。
- 模拟修复后不 saveDB 直接读盘：读到「V5.2导入公司」（正确）。
- `modals.js` / `app.js` 语法检查通过，已同步到打包工程 + 网页版交付副本（MD5 一致）。

### 27.5 排查要点（供后续同类问题参考）

1. 先区分导入走的是哪条路径：JSON 备份（`importJSON`→`applyImport`，先换内存再 save）还是账套包（`importPack`→主进程写盘）。两条路径的「内存 vs 磁盘」时序完全相反。
2. 判断「主进程是否已写盘」：凡 `window.desktop.*` 直接落盘的操作（flpack.import、backup.restoreVersion），渲染层**不得再 saveDB()**，否则旧内存必然覆盖新盘。
3. `saveDB()` 保存的永远是「当前内存 DB」——这是本 bug 的核心认知。

### 27.6 状态

代码修复已完成并同步；**未重新打包**（exe / zip 内仍是修复前的代码）。如需让安装版 / 免安装版带上此修复，需重新执行构建 + 门禁 + 更新产物。

## 三十、v5.5.9：全部可删除列表支持多选批量删除（2026-11-02）

### 30.1 需求与范围

用户要求「所有可以删除的页面都加上多选删除」。梳理出 10 个删除入口，全部接入：

| scope | 页面 | 单条删除的约束（批量时同样生效） |
|---|---|---|
| `tx` | 资金流水 | 仅管理员；票据自动分录不可删 |
| `debt` | 往来款 | 连带删除分期结清记录 |
| `acc` | 账户管理 | 系统账户不可删；已有流水的不可删（可停用） |
| `cat` | 分类管理 | 已被流水使用的只能停用 |
| `user` | 用户管理 | 内置管理员、当前登录账号、最后一个管理员不可删 |
| `company` | 公司管理 | 至少保留一家 |
| `party` | 往来单位 | 已有流水的只能停用 |
| `advance` | 借支备用金 | 直接删，不自动删已生成流水 |
| `invoice` | 票据未回 | 已报账需先撤销；删时冲销全部关联流水 |
| `project` | 项目 | 已有流水的不允许删 |

### 30.2 实现结构（一套框架，10 处接入）

| 位置 | 内容 |
|---|---|
| `core.js` | `UI.sel`（scope → Set<id>）+ `selSet/selHas/selToggle/selClear/selCount/selPrune/selKeepOnly` |
| `views.js` | `selTh(scope)` 表头全选、`selTd(scope,id,opts)` 行复选框、`bulkBar(scope)` 批量栏（已选 N 条 + 批量删除） |
| `app.js` | `DEL_CORE`（10 个纯删除函数，返回 `{ok,msg}`，不弹窗不渲染）+ `BULK_LABEL` + `updateBulkBar(scope)` + `case 'bulk-del'` + 勾选/全选的 change 委托 |
| `styles.css` | `.sel-col` 复选框列、`tr.is-selected` 行高亮、`.bulk-bar` 批量栏 |

**关键设计**：

1. **勾选不重绘**：勾选只更新 `UI.sel` 与批量栏计数/全选框状态，不调 `renderView()`——整页重绘会把正在勾的行替换掉，连续勾选会中断。
2. **重绘即清空**：`renderView()` 开头调 `selClear()`。切页 / 改筛选 / 切主题 / 切公司后，选中一律清空，避免「删到看不见的行」。
3. **批量删除走统一收尾**：`bulk-del` 的 onConfirm 循环调 `DEL_CORE[scope](id)`，统计成功数与跳过原因，一次 `saveDB + render`，toast 汇总「已删除 N 条，跳过 M 条（原因）」。
4. **禁用 + 兜底双保险**：不可删的行复选框直接 `disabled`；即使被绕过（直接调 `DEL_CORE`），函数本身仍返回 `{ok:false,msg}`。
