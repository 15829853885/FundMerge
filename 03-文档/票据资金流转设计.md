# 票据资金流转 · 详细设计（v2 定稿）

> 版本：v2 ｜ 日期：2026-10-31 ｜ 状态：**口径已冻结，按第十节实现**
> 依据：用户两轮共 11 条口径回答。
> 第一轮（7 条）：票据=付款等发票、账面资金含票据未回、借入按应付款项、报账记费用、内置账户自动生成、整张回完再进、按今日快照。
> 第二轮（4 条）：借入款完全不计入、员工未报销不计入账面资金（报销后按正常流程录入）、报账分类记一笔时预选且报账时可改、撤销报账允许但二次确认+写日志。

---

## 一、总口径（一句话）

**钱在「付款登记票据」时从现金/公户挪进「票据未回资金」，此后再怎么流转（未回→已回→未报账）账面资金都不变；只有「报账」这一步把它记成费用，账面资金才真正减少。**

这条口径同时满足你的两句话：「账面资金包含票据未回」+「只要未报账，账面资金就不变」。

## 二、四个桶与账面资金公式

| 桶 | 账户类型 | 计入账面资金 | 说明 |
|---|---|---|---|
| 现金 | `cash` | ✅ | 现有 |
| 公户 | `bank` | ✅ | 现有 |
| **票据未回资金** | `bill_pending`（新增，内置） | ✅ | 已付款、发票未整张回 |
| **未报账资金** | `unreported`（新增，内置） | ✅ | 发票已到、未报账 |
| 借支备用金 | 派生（`advances` 未核销） | ✅ | 现有 |
| 借出款 | 派生（`debts.lend` 未结清） | ✅ | 现有 |
| 借入款 | 派生（`debts.borrow` 未结清） | ❌ | **按应付款项单列**，不计入 |
| 员工未报销 | 派生（`debts.reimburse`） | ❌ | **不计入**：未付款的应付项，报销时按正常流程录一笔支出 |

```
账面资金 = 现金 + 公户 + 票据未回资金 + 未报账资金 + 借支备用金 + 借出款
应付款项 = 借入款 + 员工未报销（均单列展示，不参与上式）
净资金   = 账面资金 − 借入款（可选展示）
```

## 三、票据模型

### 3.1 字段（在现有基础上新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `amount` A | number | 现有，票面金额 |
| `receivedAmount` R | number | 现有，已回票累计 |
| `status` | `none` / `partial` / `done` | 现有，票据状态 |
| **`form`** | `unreported` / `reported` | 新增，形态；默认 `unreported` |
| **`payAccountId`** | string | 新增，付款账户（现金/公户），生成转账用 |
| **`expenseCategoryId`** | string | 新增，报账时的费用分类 |
| **`currency`** | string | 新增，默认本位币（可选） |
| **`reportedAt` / `reportedBy`** | string | 新增，报账时间与人 |
| **`txIds[]`** | string[] | 新增，本票生成的自动流水 id，用于冲销 |
| **`migrated`** | bool | 新增，期初迁移标记，防重复初始化 |

### 3.2 状态机（status × form）

```
                  ┌────────────── 回票完成（R=A）──────────────┐
  登记(未回) ──▶ none ──部分回(R<A)──▶ partial ───────────────▶ done
                  │                     │                        │
                  └─── 整张回完前不产生任何分录 ────────────────┘
                                                                 │
                                                        form: unreported
                                                                 │ 报账
                                                                 ▼
                                                        form: reported（终态）
```

- **status 只影响「钱在哪个桶」，不影响总额**：`none/partial` → 票据未回；`done` → 未报账。
- **form 只影响「是否已记费用」**：`unreported` → 未报账；`reported` → 已记费用，不可再改（除非撤销报账）。

## 四、分录表（核心）

设票据金额 A，付款账户 = 公户 P。

| # | 事件 | 前置 | 生成流水 | 账户变动 | 账面资金 | 费用/预算 |
|---|---|---|---|---|---|---|
| E1 | 记一笔·未回 | — | 转账 P → 票据未回，A | P −A，D +A | **0** | 0 |
| E2 | 记一笔·部分回 | — | 同 E1（整张未回，全额进 D） | P −A，D +A | **0** | 0 |
| E3 | 记一笔·已回 | — | 转账 P → 未报账，A | P −A，C +A | **0** | 0 |
| E4 | 回票完成 | status→done | 转账 票据未回 → 未报账，A | D −A，C +A | **0** | 0 |
| E5 | **报账** | form→reported | **支出** 未报账，A，分类=`expenseCategoryId` | C −A | **−A** | +A |
| E6 | 撤销报账 | reported→unreported | 冲销 E5（收入 未报账，A） | C +A | **+A** | −A |
| E7 | 删除票据（未报账） | — | 冲销 E1/E3/E4 | 回原账户 | 0 | 0 |
| E8 | 删除票据（已报账） | — | 冲销 E1/E3/E4/E5 | 回原账户 | +A | −A |
| E9 | 修改金额 A→A′（未报账） | — | 差额补记/冲销 (A′−A) | 按差额 | 0 | 0 |
| E10 | 修改金额（已报账） | — | **禁止**，须先撤销报账 | — | — | — |

**部分回不产生分录**（E2），只更新 `receivedAmount` 与状态——这是你「等整张回完再进」的直接结果。副作用：部分回期间，「票据未回资金」余额仍是全额 A，与旧对账单的「未回余额 A−R」不同（见 M1）。

## 六、对现有报表的影响（必须一起改，否则数字对不上）

| 报表 | 现状 | 改动 |
|---|---|---|
| 资金对账单 | 现金 + 银行 + 票据未回余额 + 借款 + 借支 | 删掉「票据未回余额」这一行（它已是账户），改为 8 项；「借款」拆成「借入款（应付款项，单列）」与「员工未报销」 |
| 主页「资金总额」 | `totalBalance()` 累加所有账户 | 会自动含 D、C，**符合你的口径**；但要检查「可用余额」类指标是否需排除 D、C |
| 支出统计 / 预算 | 按流水 `out` 汇总 | **费用改在报账日确认**：付款日不再计支出。月度支出、预算执行、分类占比都会变（见 X1） |
| 现金流量表 | 按流水 `in/out` | 付款是「账户间转账」，不再计现金流出 → **与实际现金不符**（见 X2） |

## 七、期初迁移（按今日快照）

一次性执行，给两个内置账户写**期初余额**，不生成流水：

```
票据未回资金.期初 = Σ(未报账 且 status ≠ done) 的票据金额 A
未报账资金.期初   = Σ(未报账 且 status = done) 的票据金额 A
```

同时给每张存量票据打 `migrated = true`，`form = unreported`，`payAccountId` 留空（历史付款已发生，不再回溯到具体账户）。

> 迁移后，账面资金 = 今日对账单 + Σ(部分回已回金额 R)。见 M1。

## 十一、口径冻结论断（实现时不得偏离）

1. 账面资金 = 现金 + 公户 + 票据未回 + 未报账 + 借支备用金 + 借出款；**借入款、员工未报销都不进**。
2. 登记票据 = 转账（现金/公户 → 票据未回或未报账），**总额不变**。
3. 回票完成 = 转账（票据未回 → 未报账），**总额不变**。
4. 报账 = 支出（未报账 → 费用分类），**总额减少 A**，同时计入预算与支出统计。
5. 撤销报账 = 冲销第 4 步，**总额恢复 A**，二次确认 + 日志。
6. 删除已报账票据 = 拒绝；未报账票据可删（冲销全部相关流水）。
7. 部分回不产生分录，只更新进度；「票据未回」余额始终是全额 A。
8. 期初迁移按今日快照：未回/部分回 → 票据未回账户全额 A；已回未报账 → 未报账账户全额 A。

*口径已冻结。按第十节顺序落地，每步跑完更新文档并回归。*

## 十二、实现记录（落地时对设计的两处修正）

### 12.1 「登记」统一先进票据未回，不按状态分流

原设计 E3 写的是「登记时直接选已回 → 转账 P → 未报账」。实现时改成：**登记永远先进票据未回，再由 `receive-done` 转入未报账**。

原因：如果 register 按状态分流，而调用方又按「status=done 就补发 receive-done」的写法（编辑重发流水时会这样），同一条路径就会**重复扣减票据未回**、把未报账加两次。统一成「先入票据桶 → 整张回完再转」只有一条路径，不会重复。

副作用：登记即已回的票据会多一条金额相同、方向相反的当天转移流水（进票据桶再出票据桶），余额最终一致，多出的流水有审计价值。

### 12.2 撤销报账用「删除报账流水」，不是「冲销分录」

原设计 E6 写的是「冲销 E5（收入 未报账，A）」。实现改成**直接删除那笔报账支出流水**。

原因：冲销会留下「支出 A + 收入 A」两条记录，净额虽然是 0，但**分类支出统计会虚高 A**（本月办公费会平白多出一笔又冲回）。自动流水是票据的附属物，删除后按当前状态重算最干净；审计由 `logAction` 的 before/after 承担。

### 12.3 新增的数据层防护

- `postInvoice()` 拒绝 `form === 'reported'` 的票据：已报账的票不再产生任何内部流转，防止调用方重复记账。
- `removeInvoicePostings()` 按 `fromInvoice` + `txIds` 双条件清理，兼容早期没有 `txIds` 的数据。
- 系统账户在后端三处（编辑 / 删除 / 对账调整）都加了守卫，不只靠界面隐藏按钮。
