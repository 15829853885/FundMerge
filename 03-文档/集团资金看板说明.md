# 合资金账 FundMerge · 集团资金看板说明

> 适用版本：v5.5 ｜ 更新：2026-10-31 ｜ 页面：集团 → 资金看板 ｜ 代码：`assets/views.js`（`viewFlowBoard` / `fb*`）+ `assets/flowboard.js` + `assets/core.js`（`groupFlowMatrix`）

---

## 一、这个页面解决什么问题

集团总览回答的是**存量**：每家现在有多少钱、这个月收了多少、谁欠谁。
资金看板回答的是**流量**：钱在集团内部怎么走——谁转给谁、转了多少、几笔、占多大比重。

两个页面共用同一份账本，不存在"看板一个数、总览另一个数"。差别只在口径：总览算余额与收支，看板只算集团内部的资金移动。

## 二、页面结构

| 区域 | 内容 | 数据来源 |
|---|---|---|
| 顶部工具栏 | 区间（本月/本季/本年/全部）、公司间转账入口、返回集团总览 | `UI.fbPreset` |

| 内部流转趋势 | 近 6 个月转账 + 代付堆叠柱，点月份看该月明细 | `groupFlowTrend()` |
| 各公司资金分布 | 区间末账面资金环形图 + 图例，点扇区看该公司流向 | `groupFlowMatrix().nodes` |

| 净流向排行 | 各公司净流向（居中双向条）、区间末余额、最近流向时间线 | 同上 |

## 三、口径（唯一来源：`groupFlowMatrix`）

### 3.1 计入

| 情形 | 取哪条记录 | 金额折算 |
|---|---|---|
| 公司间转账 | 付款方公司里 `type='transfer' && direction!=='in'` 的那条 | 按付款账户币种折本位币 |
| 集团代付 | 子公司账上 `noCash && fundedBy` 的流水 | 按总公司出资账户币种折本位币 |

公司间转账在两家公司各存一条镜像，**只取付款方那条**；历史脏数据里同一 `pairId` 出现两条 out 的，按 `pairId` 去重。

### 3.2 不计入

| 情形 | 原因 |
|---|---|
| 同一家公司内部的账户互转（无 `peerCompanyId`） | 钱没离开这家公司 |
| 对外收付款、借支、报销、票据 | 属于公司与外部/员工的往来 |
| 缺汇率的外币流水 | 绝不按 1:1 静默折算（REQ-22），改为在状态栏用橙色提示缺哪种币 |

### 3.3 派生字段

```
nodes[]  = { id, name, color, isParent, inAccounting, balance, inflow, outflow, count }
edges[]  = { from, to, amount, count, transfer, pay, lastDate, lastSummary }
totalFlow = transferTotal + payTotal
pairCount = edges.length
totalCount = Σ edges.count
```

`nodes` 会为**所有公司**建条目（即使区间内没有流向），余额取 `companyBalanceAt(co, to)`。目的：3 家公司但本月没有内部转账时，图里仍然画出 3 个节点，而不是显示"还看不出集团内流向"——后者会让人以为数据没读到。

## 四、关系图怎么排、怎么画

- **布局**：圆环。按余额倒序后从 12 点方向依次排布，位置是**确定**的（不是力导向），第二次进来能靠位置记住公司。
- **节点半径**：`21 + 13 × √(余额/最大余额)`。开方是为了让余额差距小的公司看起来也差不多大，否则小公司会变成一个点。
- **丝带**：从付款节点边缘到收款节点边缘的二次贝塞尔，控制点向圆心收 44%，形成"弧"。
  - 线宽 `1.5 + 9.5 × (金额/最大金额)^0.62`：开方映射，线性会让最大一笔把其余压成 1px 细线。
  - 反向成对（A→B 与 B→A）时，第二条垂直偏移 16px，避免完全重合。
- **流动点**：同一条路径上叠一条 `stroke-dasharray: 2 15` 的虚线，用 `stroke-dashoffset` 做位移（只动合成层，不触发 SVG 重排）。金额越大，动画越快（2.9s → 1.4s）。
- **颜色**：靛蓝=公司间转账，橙=集团代付；节点光环与描边用公司自己的颜色（`co.color`），净流向文字红正绿负（国内习惯）。

## 五、实时刷新机制

| 触发 | 延迟 | 实现 |
|---|---|---|
| 定时器 | 每 5 秒 | `setInterval` → `paint(false)` |
| 本窗口写库 | 约 300ms（防抖） | `saveDB()` 里 `dispatchEvent('fm:db-saved')` → 监听 |
| 其它窗口写库 | 即时 | `window.addEventListener('storage')`，只认 `STORE_KEY` |
| 手动 | 立即 | 「刷新」按钮 → `FlowBoard.refresh()` |

**关键设计：先比签名，再决定要不要改 DOM。**

```js
const sig = d => JSON.stringify([...金额、笔数、余额、最近日期...]);
if (!force && sig(d) === lastSig) return;   // 没变就只更新时间戳
```

原因：真实账本 5 秒内绝大多数时候没有变化。无条件 `innerHTML` 会让用户正悬停的丝带每 5 秒闪一下，正在看的表格也会被重建。变化时才替换四个区域（`#fb-kpis` / `#fb-graph` / `#fb-rank` / `#fb-table`），并给替换过的区域加 `.is-fb-flash` 闪一次底色，提示"这块刚变过"。

**停表条件**：切走页面（`renderView` 里 `FlowBoard.stop()`）、退出登录（`renderAuth` 里停）、页面隐藏（`visibilitychange` 清 interval，恢复可见立即补一次）。

**暂停/恢复**：结果写入 `localStorage['fm-fb-live']`，启动时 `UI.fbLive = localStorage.getItem('fm-fb-live') !== 'off'` 读回，所以"暂停"跨重启有效。暂停时仍可手动刷新。

## 六、适用范围与已知边界

| 边界 | 说明 | 处理 |
|---|---|---|
| 只有结构化记录才进看板 | 当时若把转账录成了普通支出，不会出现在看板 | 到「资金流水」核对修正；不做文本猜测匹配 |
| 借支/拨款分类的流水 | `拨款给子公司` 等分类若未带 `peerCompanyId`，不算跨公司流向 | 用「公司间转账」重录，或后续版本补分类到公司的映射 |
| 总公司不参与合并（registry 模式） | 总公司仍出现在图中（它是真实付款方），但余额不计入合并合计 | 节点数据里保留 `inAccounting` 标记，KPI 合计只累加参与合并的公司 |
| 多币种 | 按发生日汇率折本位币；缺汇率跳过并提示 | 与全站口径一致 |
| 公司数量 | 2–8 家最合适；超过 8 家圆环会拥挤 | 明细表始终可读；后续可加"只显示 Top N 流向" |

## 七、验收要点（可直接照做）

1. 造 3 家公司，A→B 转 5 万 + 2 万、B→C 转 1.8 万、C→A 转 6 千，A 替 B 代付 3 千。
2. 看板应显示：流转总额 9.7 万、公司间转账 9.4 万、集团代付 3 千、4 组流向、5 笔。
3. 图里 3 个节点、3 条丝带；A→B 那条最粗（7.3 万，含代付）。
4. 在别的页面新增一笔 A→C 转账并保存，回到看板（或停在看板），1 秒内数字变化且该区域闪一次。
5. 点「暂停」，指示灯熄灭；此时改数据等 6 秒，数字不动；点「继续」，立刻补一次刷新。
6. 关掉「设置 → 交互反馈」，粒子与追光消失，页面入场动画仍在。
7. 深色主题下悬停卡片，应看到品牌色光晕 + 1px 亮环（不是"没反应"）。

## 九、信息维度（第二轮补充）

第一版只有"四个总数 + 一张关系图 + 一张表"，回答不了"最近在变多还是变少""钱主要压在谁手上"。第二轮补了两张卡：

| 卡片 | 回答的问题 | 数据口径 |
|---|---|---|
| 内部流转趋势 | 最近 6 个月集团内流动在放大还是收缩？哪个月是峰值？ | `groupFlowTrend(to, 6)` 逐月调用 `groupFlowMatrix`，与主图**同一套口径**，不另写算法 |
| 各公司资金分布 | 集团的钱主要在哪几家公司账上？ | 各公司 `inAccounting === true` 且余额 > 0 的区间末账面资金 |

同时把指标卡的脚注补全：流转总额卡多了"平均每笔"，转账/代付卡多了"笔数"，最大流向卡多了"笔数"。

## 十、点击下钻（交互映射）

看板上所有可点的位置都收敛到同一个事件 `fb-open`，只写筛选条件然后跳 `flow-detail` 页：

| 点击对象 | scope | 目标页看到的内容 |
|---|---|---|
| 集团内流转总额卡 | `all` | 当前区间内全部逐笔流向 |
| 公司间转账卡 | `kind=transfer` | 只含公司间转账的逐笔 |
| 集团代付卡 | `kind=pay` | 只含集团代付的逐笔 |
| 最大的一组流向卡 | `edge` | 这一组（付款方 → 收款方）的逐笔 |
| 关系图丝带 | `edge` | 同上 |
| 关系图圆环 / 分布图扇区 / 分布图例 | `company` | 与这家公司有关的全部流向（收 + 付） |
| 净流向排行行 | `company` | 同上 |
| 最近流向行 | `edge` | 该组逐笔 |
| 明细表行 | `edge` | 该组逐笔 |
| 趋势柱 | `month` | 该自然月的全部流向（区间自动切成月初～月末） |

下钻页 `viewFlowDetail()` 的结构：面包屑 → 标题（A → B / 与 X 有关 / 某月）→ 汇总条（合计、笔数、转账、代付、涉及公司）→ 逐笔表（日期、来源、去向、类型、金额、摘要、凭证号）→ 口径说明。表里的公司名可点，直接进入该公司账本。

**为什么单独做一页而不是复用「资金流水」**：流水页是"单公司 + 账户维度"的，一组跨公司流向在两家公司各有一条记录，在单公司流水里永远看不全；`flow-detail` 是"组维度"的，天生跨公司。

## 十一、两个系统账户与看板的关系

「票据未回资金」「未报账资金」是票据流转的中间桶，它们的流水全部是**同一家公司内部**的账户互转（付款账户 → 票据桶 → 未报账桶 → 费用支出）。

因此：

- 它们**不会**出现在看板的任何流向里（`groupFlowMatrix` 只认 `peerCompanyId` 与 `noCash/fundedBy`）；
- 它们也**不会**出现在任何手工记账的账户下拉里（统一走 `manualAccounts()`）；
- 票据自动生成的分录在「资金流水」页带「票据自动」标记，编辑/删除按钮换成「去票据」，不能绕过票据页直接改。

这三点合起来保证：看板上的"集团内流向"永远只反映**公司之间**的资金移动，不会被票据桶的内部结转污染。

## 十二、验收补充（第二轮）

1. 看板应出现 6 根趋势柱、3 个分布扇区；趋势柱高与当月合计成比例。
2. 点任一指标卡 → 进入「流向明细」，标题为"全部集团内流向"，逐笔数与 KPI 笔数一致。
3. 返回后点最粗的丝带 → 标题为"A → B"，行数等于该组笔数（2 笔转账 + 1 笔代付 = 3 行）。
4. 点排行行 → 标题"与 X 有关的流向"；点趋势柱 → 标题以"YYYY年M月 ·"开头。
5. 下钻页面包屑可返回看板；公司名可点进对应账本。
6. 账户页两个系统账户只显示「明细 / 自动维护」，无编辑、删除、对账；票据分录在流水页不能直接编辑或删除。
