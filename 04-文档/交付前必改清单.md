# 交付前必改清单（FundMerge）

> 适用版本：**v5.2.0+** ｜ 最近整理：2026-10-30
> 用途：每次发版前逐项打勾。**这份清单的存在理由**——v5.0.0 交付时全靠记忆更新文档，漏了操作手册与收尾交付说明，补完还得重走一遍构建 + 打包 + 280MB LFS 推送；v5.2.0 又因为「文档没同步进打包工程」连着重打了三次包。清单化就是为了不再靠记忆。

---

## 0. 怎么用

- 按阶段顺序走，**不要跳步**。第 3 阶段（构建）失败时回头改代码，改完必须从第 2 阶段重来。
- 每项后面的「验证」列是**可执行的命令或动作**，不是"检查一下"这种空话。
- 打不了勾的项，写清原因和责任人，不要留空。

## 1. 阶段一：代码改完了吗

| # | 检查项 | 为什么 | 验证方式 |
|---|---|---|---|
| 1.1 | 版本号**两处**同改 | `artifactName` 用的是 `${version}`，会自动跟；真正要手改的是这两处，漏一处就会出现"装的是新版、显示是旧版" | `package.json` 的 `version`、`assets/core.js` 的 `APP_VERSION` 两处比对 |
| 1.2 | 新增账本数组加进 `COMPANY_KEYS` | 代理只认这几个键（`accounts/transactions/debts/settlements/budgets/categories`），新数组不加进去，`DB.xxx` 会静默 `undefined`，不报错、只出错数 | 搜 `COMPANY_KEYS`（core.js）看有没有漏 |
| 1.3 | 新增字段在 `normalize()` 里补了默认值 | 老数据文件不会带新字段，不补默认值会读出 `undefined` 再参与计算 → NaN | 用旧版 `data.json` 启动一次，看有没有 NaN |
| 1.4 | `noCash` 口径没有搞反 | 资金类（余额/净流入/现金流量/集团合并）**要过滤**；费用类（预算已用/项目支出/支出构成）**不能过滤**，过滤了会让预算虚低、超支提醒延迟 | 搜 `noCash` 全部命中点，逐个判断属于哪类 |
| 1.5 | 改聚合函数时没引入 O(n×m) | `companyBalanceAt` 若改成逐账户调 `balanceOf`，趋势图 200 点 × 3 万流水会卡死 | 趋势图切"本年"，看是否秒开 |
| 1.6 | **孤儿流水仍然被排除，不是按 1:1 计入** | v5.2.0 修的核心：`txBase` 查不到账户返回 0，`companyBalanceAt` 跳过；一旦有人"顺手"改回 `\|\| baseCurrency()`，多币种金额又会静默失真 | 造一条 `accountId='ghost'` 的流水，断言 `txBase === 0`、合计不含它 |
| 1.7 | **归一化不再静默丢账户** | 账户缺 id 要补 `uid('a')`，不能 `filter(a => a.id)`；流水缺 id/日期必须丢，但要计数上报 | 造缺 id 账户，`normalize()` 后账户仍在且有 id |
| 1.8 | 导入校验同时认新旧结构 | v5.0.0 踩过：`applyImport` 只认顶层 `data.accounts`，自己导出的 `{companies:[]}` 反而导不回来（P0） | 导出账套 → 立即导入 → 公司数/流水数/本位币不变 |
| 1.9 | 全量脚本语法通过 | 少个括号整个页面白屏 | `for f in assets/*.js electron/*.js; do node --check "$f"; done` |

## 2. 阶段二：测过了吗

| # | 检查项 | 为什么 | 验证方式 |
|---|---|---|---|
| 2.1 | 本轮改动逐条有断言 | DEF-02 的教训：上一轮声称"项目笔数已修"，其实只改了金额分支。**"改了"必须被用例证明，不能靠回忆** | 对着本次改动清单逐条找断言；找不到就补 |
| 2.2 | 三角色 × 20 页全渲染 | 权限改动最容易在某类用户下白屏 | `startSession(role)` → `renderShell()` → 遍历 `UI.view`，检查 `#view-root` 非空、无 error 事件 |
| 2.3 | 页面 0 NaN / 0 undefined | 断言只看关键字，NaN 是最容易漏的 | 冒烟结果里 `nanCount`、`undefCount` 都为 0 |
| 2.4 | 畸形数据不崩 | 一个损坏的备份文件能让软件起不来（DEF-03） | 20 组畸形结构模糊测试，全部安全归一化 |
| 2.5 | 大数据量首屏可接受 | 30,000 笔时全量渲染应 < 500ms | 生成 3 万笔后测一次，记录数字 |
| 2.6 | 长稳无内存泄漏 | 反复切页若每次泄漏，跑久了会崩 | 5000 笔下 1500 轮切页，内存增长应为 0MB |
| 2.7 | 云盘真实环境通过（如本版动了备份） | 配置加密、连接、上传、版本索引、下载回读、恢复覆盖、删除、错误凭据 | `%TEMP%\fm-cloud\`，凭据走环境变量，**测完删临时目录** |

## 3. 阶段三：构建与门禁

| # | 检查项 | 为什么 | 验证方式 |
|---|---|---|---|
| 3.1 | **在工作区外构建** | 工作区内 `electron-builder` 解包后要 `rename win-unpacked.tmp → win-unpacked`，而新生成的 `app.asar` 会被快照服务立刻独占 → `EPERM`。**这是必然失败，不是偶发** | 复制到 `%TEMP%\fm-buildNN`，排除 `node_modules`/`dist`/`.git` |
| 3.2 | `node_modules` 用目录联接，不要复制 | 复制 455MB 太慢 | PowerShell `New-Item -ItemType Junction`。**不能用 `cmd /c mklink`**，会被安全策略拦 |
| 3.3 | 同步源码时用 `-Path` 不用 `-LiteralPath` | `-LiteralPath` 不展开通配符，会静默不同步 | 同步后逐个 MD5 比对，必须全 same |
| 3.4 | **打包前把 10 份文档全部同步进打包工程** | `extraFiles` 的 `from` 是**打包工程根目录**，不是 `04-文档`。v5.2.0 就因此重打三次：包里带的是旧版报告（5.1.0）和旧版打包说明（v5.0.0） | 构建后 `grep -c "v5.2.0" dist2/win-unpacked/文档/*.md`，逐份确认 |
| 3.5 | 门禁 PASS | 结构断言 + 文本扫描 + 版本一致性 | `sh deliverables/pack-gate.sh dist2`，要求 `asar=X exe=X`、0 告警 |
| 3.6 | 打包版真能启动 | 构建成功 ≠ 能运行 | 用临时数据目录启动 `win-unpacked\合资金账.exe`，检查是否生成 `data.json` 且结构正常 |

## 4. 阶段四：产物打包（四个目录）

| # | 检查项 | 为什么 | 验证方式 |
|---|---|---|---|
| 4.1 | `01-安装版` 只放本次 exe | 旧版本 exe 留在里面，别人会装错 | 目录内只应有一个 `FundMerge-Setup-X.Y.Z.exe`，时间戳是本次构建 |
| 4.2 | `02-免安装版` 的 zip 更新 | 只更新目录不重打 zip，别人下到的是旧包 | zip 内 `resources/app.asar` 的 MD5 与构建产物一致 |
| 4.3 | zip 直接由 `win-unpacked` 打，不在交付目录留解压副本 | 交付目录里的 `app.asar` 极易被索引/杀软占用，删不掉也改不了名（v5.2.0 就卡在这），白占 358MB | `zipfile` 遍历 `win-unpacked` 写入，条目前缀用 `合资金账-X.Y.Z-portable/`；解压目录写进 `.gitignore` |
| 4.4 | `03-网页版` 脚本与手册同步 | 网页版是独立拷贝，不跟着自动更新 | `assets/` 全量覆盖，`manual.html` MD5 与 `04-文档/操作手册.html` 一致 |
| 4.5 | `04-文档` **十份**齐全 | 见 5.1 | 逐份点名 |
| 4.6 | 体积记录 | 交付说明里要写 | 四个目录各多大，写进收尾说明 |
| 4.7 | 交付目录只留四个文件夹 + `README.md`/`LICENSE` | 给别人用的包不该混进打包工程、测试报告、内部清单 | `ls` 顶层，多余项移到 `项目档案/` |

### 5.2 操作手册是**双重身份**（v5.0.0 踩过）

`assets/manual.html`（软件内「使用手册」按钮打开的）与 `04-文档/操作手册.html` 是**同一份文件**，MD5 相同。

改手册必须走完这条链，缺一步装出来的软件里还是旧手册：

1. 改 `04-文档/操作手册.html`（或改 `assets/manual.html` 再覆盖过去）
2. 复制到 `assets/manual.html`
3. 复制到 `FundMerge-打包工程/assets/manual.html`
4. **重新构建**（手册在 `app.asar` 里）
5. 重打免安装版 zip
6. 网页版 `assets/manual.html` 覆盖

## 9. 附：v5.2.0 的完整改动清单

供下次改动时参考改动面。

### 9.1 数据模型 / 口径变化

| 位置 | 变化 |

## 10. 一句话总结

**能靠命令验的，就不要靠记忆；能写进用例的，就不要写进"应该改过了"。**

这份清单里每一条"为什么"，都是实际踩过一次的坑——最后三条（extraFiles 取文档的位置、交付目录里的 asar 会被锁、LFS 上传要等）是 v5.2.0 新加的。
