## 一、这是什么

**合资金账 FundMerge** 是面向中小企业（主要在加纳）的 **Windows 桌面资金管理软件**。

| 特征 | 说明 |
|---|---|
| 运行形态 | Electron 45 打包的单个 exe 安装包，装完即用 |
| 离线 | **完全离线**。无 CDN、无字体外链、无自动更新。实测阻断全部 http(s) 后功能正常 |
| 多公司 | 一个账号管多家公司，账本完全隔离；另有集团合并视图 |
| 集团模型 | 总公司持资金，可拨款、可代子公司付款 |
| 数据 | 默认在 `<安装目录>\data`；另有账套包 `.flpack` 作为交付/迁移单位 |
| 交付物 | 安装包 + 四份文档（操作手册、交接说明、需求解读、打包发布说明） |

**核心设计取向**：数据在用户手里（可进文件夹看、可整目录复制、可导出单一账套包）；不引入网络依赖；不做"看起来能用实际不安全"的功能。

## 二、技术栈

| 层 | 技术 | 备注 |
|---|---|---|
| 桌面壳 | Electron 45（Chromium 140 / Node 20+） | `contextIsolation: true`、`sandbox: true`、packaged 版关闭 devTools |
| 渲染层 | **原生 HTML/CSS/JS，无框架、无构建** | `file://` 不支持 ES module，五个脚本按顺序加载 |
| 图表 | 手写 SVG 字符串 | 不引图表库（离线硬要求） |
| 3D | three.js r152 UMD（本地 619KB） | 仅装饰；弹窗打开时暂停渲染 |
| 存储 | 桌面：JSON 文件 + 附件目录；网页：localStorage + IndexedDB | |
| 密码 | PBKDF2-SHA256 + 16 字节随机盐（WebCrypto） | |
| 账套包 | 自研 STORE 模式 ZIP + 可选 AES-256-GCM | 产物是真 ZIP，可用 7-Zip 打开 |
| 云盘凭据 | Electron `safeStorage`（绑定 Windows 账户） | 存 `%APPDATA%\FundLedger\backup.json` |

**脚本加载顺序**（`index.html`，不可打乱）：

```
core.js → ui.js → views.js → modals.js → vendor/three.min.js → scene.js → app.js
```

## 四、构建与发布

```bash
npm install
node node_modules/electron-builder/cli.js --win --x64 --config.directories.output=dist
```

产物：`dist/FundMerge-Setup-<ver>.exe`（约 116MB）+ `dist/win-unpacked/`。

### 4.1 构建必踩的坑

1. **先结束 `合资金账.exe` 进程**，否则解包阶段 EBUSY。
2. **输出目录不能有 `win-unpacked.tmp` 残留**。某些环境的 safe-delete 垫片会把 `fs.rm` 转成"回收站"，大目录 trash 失败 → 报 `[safe-delete] 操作失败`。规避：换新的输出目录名。
3. **不要用 `mv dist dist_old` 替换产物**，文件系统视图延迟时会误删产物。直接 `cp` 安装包。
4. **electron-builder 的 `build.productName` 与 `build.win.artifactName` 会覆盖顶层同名配置**。只改顶层不生效——v4.0.0 踩过，出来的还是旧名字。
5. 未配置代码签名证书 → 安装时出现 SmartScreen「未知发布者」，属正常。

### 4.2 发版门禁（必须跑）

```bash
sh deliverables/pack-gate.sh --self-test   # 验尺子：6 例自检
sh deliverables/pack-gate.sh dist          # 验产物：结构/凭据/版本一致性
```

退出码 0 才允许发布。**注意**：`node pack-scan.js dist | tail` 的退出码是 `tail` 的（恒 0），必须用包装器。

门禁查三类：A 结构断言（禁止 `data/`、`*.bak.json`、`debug.log`、开发文档）、B 文本扫描（明文凭据、手机号、本机路径）、C 版本一致性（asar 版本必须等于 exe 版本）。

> **门禁是"自证型"**：执行者与被验证者是同一个人。它能防无意改动与夹带，**不防有意绕过**。真正防恶意需要 CI 从干净 checkout 运行。

### 5.1 `cf` 字段（现金流量项目）

决定该分类归到现金流量表哪一行：`none` / `op_in_sales` / `op_in_other` / `op_out_purchase` / `op_out_salary` / `op_out_tax` / `op_out_other` / `inv_*` / `fin_*`。`none` = 不计入。

### 5.2 代理属性（重要）

`DB.accounts` / `DB.transactions` / `DB.categories` 等是 **`attachCompanyProxy()` 挂的代理属性**（`enumerable: false`），指向当前 `COMPANY`。这是 v3.0.0 为了让 v2 视图代码零改动而做的兼容层。

**新代码请优先用 `COMPANY.xxx`，或给函数传 `co` 参数。不要依赖代理做新逻辑。**

## 六、核心业务规则（改动前必读）

### 6.1 余额

```
账户余额 = 期初余额 + 收入 − 支出 − 转出 + 转入
```

`balanceOf(acc, upto, co)` 支持按日期截断。

### 6.2 不进统计的流水

- 内部转账（同公司账户互转）
- 公司间转账（`peerCompanyId` 存在）
- 集团代付的子公司侧记录（`noCash: true`）
- 分类 `cf === 'none'` 的流水（如余额调整）

### 6.3 集团总公司（`isParent`）

全集团唯一。勾选新的会自动取消旧的。作用：持资金、可拨款、可代付。

### 6.4 集团代付

子公司记账时选「总公司账户」付款 → 子公司流水 `accountId: ''`、`noCash: true`、`fundedBy`；
`syncGroupMirror()` 在总公司账上生成镜像（分类「对子公司代付」、`mirrorOf` 指向源流水）。

- 子公司余额**不变**，总公司余额**减少**
- 集团总额只减少一次
- 编辑/删除时用 `syncGroupMirror` / `removeLinkedTx` 维护镜像

### 6.5 公司间转账

一次生成两条：转出方 `direction:'out'`、转入方 `direction:'in'`，共享 `pairId`。
双方 `cf` 均为 none，不影响收支统计；集团总额不变。**不支持直接编辑**，删除时连带删除配对。

### 6.6 总公司登记方式（`parentMode`）

- `company`（默认）：总公司作为独立公司参与合并
- `registry`：仅作集团登记主体，不参与合并计算
- `accountingCompanies()` 统一过滤，`groupTotals()` 已按此口径

### 6.7 附件归档

```
<数据目录>/files/<公司ID>/<YYYY-MM>/<YYYYMMDD-HHmmss>_<名称>.<ext>
```

元数据只存 `relPath`（相对数据目录，正斜杠）。所有文件 IPC 用 `path.resolve` 前缀校验防目录穿越。

### 6.8 其它硬规则

- 有流水的账户不能删，只能停用；被使用的分类同理
- 对账差异通过「余额调整」分类的流水实现，不改期初余额
- 往来结清自动生成对应流水
- 金额 2 位小数、千分位；**流入红、流出绿**（国内习惯）
- 导出 JSON 不能带 BOM；BOM 只加给 CSV
- 破坏性操作必须 `requireCode: true`（随机 4 位数字）

### 6.9 云盘备份版本池（v4.9）

- 备份对象 = 完整账套包 `.flpack`
- 手动 + 自动**统一池**，上限 **7 个**，超限删最旧（云端 DELETE + 索引移除）
- 索引存 `%APPDATA%\FundLedger\backup-index.json`，云盘不可用也能查历史

### 13.1 动效卡顿：四个根因与对应改法

| # | 根因 | 位置 | 改法 |

### 13.2 新增「界面流畅度」三档

- `perfMode()` 读 `localStorage['fm-perf']`：`auto` / `smooth` / `rich`
- `detectGpu()` 在 boot 时通过 IPC `sys:gpu` 问主进程要 `app.getGPUFeatureStatus()`，把结果写进 `documentElement.dataset.gpu`（`hw` / `soft`）
- `applyPerf()` 据此设置 `data-perf="low|high"`
- CSS 侧 `html[data-perf="low"]` 关闭：装饰光晕、3D 画布、入场与行动画、悬停位移与阴影、按钮缩放、弹窗回弹、环形图放大、侧边栏过渡

**新增 IPC**：`ipcMain.handle('sys:gpu')` → `{ ok, compositing, hardware, rasterization, webgl, softwareRender }`；preload 暴露 `window.desktop.gpu()`。

⚠️ 注意：`app.getGPUFeatureStatus()` 在**窗口创建前**会返回 `disabled_software`（GPU 进程尚未初始化）。必须在窗口 ready 之后取，否则会误判成「没有显卡」而全量降级。实测同一进程：启动时 `gpu_compositing: disabled_software` → 窗口就绪后 `enabled`。

### 13.4 踩过的坑（v5.0.1 新增）

1. **`position: absolute` 的装饰元素会撑出横向滚动条**：把 fixed 改成 absolute 后，`right: -180px; width: 680px` 让页面多出 168px 横向滚动，兼容性用例（I03）三个宽度全部失败。装饰性溢出必须用背景图或 `overflow: clip`，不能用定位硬怼。
2. **`app.getGPUFeatureStatus()` 有时序**：见 13.2 的警告，窗口就绪前后结果相反。
3. **3D 上下文可以复用**：`canvas` 被 `innerHTML` 替换后虽然脱离了文档，WebGL 上下文仍然有效，`replaceChild` 塞回去就能继续用，不必重建。
4. **测试期望要跟着口径走**：G23 一开始断言「registry 模式下合计为 0」，实际应是「只并分公司、不含总公司」。写断言前先把口径推一遍。

## 十四、v5.0.1 修订（2026-10-29）—— 视觉与动效升级

### 14.1 动效令牌（`assets/styles.css` 顶部）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--ease-standard` | `cubic-bezier(.22,1,.36,1)` | 元素**出现**：弹窗、页面、浮层、表格行 |
| `--ease-exit` | `cubic-bezier(.4,0,1,1)` | 元素**消失**：退场用加速曲线 |
| `--ease-move` | `cubic-bezier(.4,0,.2,1)` | **原地**变化：hover、focus、折叠、主题 |
| `--dur-0..4` | 90 / 120 / 200 / 260 / 320ms | 均乘 `var(--motion-scale)`，设置页三档继续有效 |
| `--dur-shake` | 320ms | 校验抖动专用，不与 `--dur-4` 共用 |

`--ease` / `--ease-soft` 是**兼容别名**（26 处旧引用），删除会让这些 `transition` 简写整条失效、全站静默停动，不得清理。`--dur-4` 与 `--ease-exit` 当前无消费者，为下钻与弹窗退场预留，同样不得按"死令牌"删除。

曲线原则：**入场用减速、退场用加速、hover 用对称**。三者混用是"廉价感"的主要来源——入场若用对称曲线会显得拖沓，hover 若用减速曲线回程会拖。

节奏调整：页面切换 stagger 由 `0/40/75/105/130/150` 改为 `0/24/44/60/72/80`；表格行入场由前 8 行 200ms 收到前 6 行 180ms；弹窗由 `translateY(10px) scale(.975)` 改为 `translate3d(0,8px,0) scale(.98)`；5 处 `animation-fill-mode: both` 改为 `backwards`（`both` 的 forwards 段会冻结终态、挡住后续 class 下发的 transform，属可维护性问题，不是性能问题）。

### 14.2 一并修掉的显示缺陷

1. `tr:hover td { background:#fafbfd }` 以不透明底覆盖了 tr 级品牌色 hover——`td` 背景绘制在 `tr` 之上，25 张表的品牌 hover 从未生效。已删除该行，只保留 `tr` 上色。
2. `.stat:hover` 未限定 `.is-clickable`，4 张不可点击的指标卡在"假装可点"。已改为仅可点击卡抬升。
3. 深色主题对比度：`.auth-err`（登录失败唯一反馈）、`.pill` 四色、`.alert` 三态、`.import-errors`、`.cf-total` 共 9 处。**修法只加 `[data-theme="dark"]` 覆盖，浅色主题字色一字未动**——浅色下这些值本已达标，改语义令牌反而会让 `.pill.ok` 从 4.6:1 掉到 3.6:1。
4. 文本框的 `outline:none` 特异性高于全局 `:focus-visible`，键盘 Tab 到录入框无任何可见焦点。已补 2px 实线单环（`outline-offset:0` + 压掉装饰光晕），错误态环跟随 `--danger`。

### 14.3 键盘与读屏（`app.js` / `ui.js` / `index.html`）

- `enhanceA11y()` 在每次重绘后给**非原生控件**上的 `[data-action]` 补 `tabindex="0"` 与 `role="button"`，并给 `thead th` 补 `scope="col"`、当前导航项补 `aria-current="page"`。此前指标下钻与进入公司账本对键盘用户完全不可达。

- `WRITE_ACTIONS` 白名单 + 点击/change/菜单三处守卫；`applyViewerReadOnly` 隐藏写按钮、禁用预算输入。

### 18.6 数据健壮性（用户 id 兜底）
- `normalize()` 给没有 id 的用户补 `uid('u')`（与 `normalizeCompany` 的 `c.id` 兜底一致）：导入账套/早期数据里的用户缺 id，会让 `SESSION.id = undefined`，用户列表里 `data-id="undefined"`（字符串），编辑/重置密码/删除全部静默失败。
- `viewUsers` 的 `data-id` 兜底为 `u.id || ''`，「不能删除当前登录账号」判断改为 `u.id && u.id === SESSION.id`。

### 18.7 体验复核低优先项收口

**A1 嵌套 label 合规化**：认证表单（首次使用 / 登录 / 注册 / 找回密码 / 初始化）共 21 处 `<label class="field"><label>X</label>` 改为 `<label class="field"><span class="lbl">X</span>`。label 套 label 不符合 HTML 规范，内层 label 无 `for` 也未包裹控件；改用 `span.lbl` 与 `modals.js` 的写法一致。同时 `.auth-form .field > .lbl` 补上与 `.field > label` 相同的 12px 字号（原 `.auth-form .field > label { font-size:12px }` 会因标签名变化失配）。

**A6 查看员写按钮：隐藏 → 禁用**：`applyViewerReadOnly` 原为 `display:none` 隐藏写按钮；改为 `disabled`（按钮/输入）+ `aria-disabled` + `title="查看员为只读权限"`，非按钮元素（如可点击卡片）改为 `opacity:.45` + `cursor:not-allowed`。理由：让查看员看到「这里有功能但没权限」，比凭空消失更易理解权限边界。点击守卫 `WRITE_ACTIONS` 仍保留作后端兜底。

## 十九、v5.2.0：数据完整性收口（2026-10-30）

> 说明：这批改动原按 v5.1.0 推进，发布前确定最终版本号为 **v5.2.0**，代码与文档已统一改为 5.2.0。

### 19.1 孤儿流水不再按 1:1 折算（核心修复）
- **问题**：`txBase()` 原为 `const cur = acc ? accCurrency(acc) : baseCurrency()`，账户查不到时把币种替换成本位币 → `baseRate()` 走 `cur === base` 返回 1 → 金额按 1:1 计入合计。这违反 REQ-22「绝不按 1:1 静默折算」，多币种账套金额静默失真（方向取决于汇率，`rate > 1` 少计、`< 1` 多计）。
- **修复**：新增 `txAccount(t, co)`（accountId → fundedAccountId）与 `isOrphanTx(t, co)`（排除 noCash 镜像分录）；`txBase()` 遇到孤儿流水直接返回 `0`（排除），不再取本位币。
- **同步**：`companyBalanceAt()` 的分桶由 `accCur.get(t.accountId) || base` 改为查不到就 `continue`，孤儿流水不进任何桶。

### 19.2 数据质量提示聚合
- 新增 `dataQualityIssues()`：把 `missing-rate` / `orphan-tx` / `dropped-tx` / `repaired-account` 聚合成「一条问题 + 对应处置入口」。**没有**把孤儿流水塞进 `missingRateCurrencies()`（那是按币种计数 + 「去录入汇率」按钮，治不了孤儿流水）。
- `app.js` 的页面提示条由「只报缺汇率」改为按 `dataQualityIssues()` 逐条渲染：缺汇率→去录入汇率；孤儿流水→查看流水；被跳过的流水 / 补齐标识的账户→仅说明。

### 19.3 归一化不再静默丢数据
- `normalizeCompany()`：账户缺 id 由「`filter(a => a.id)` 丢弃」改为**补 `uid('a')`**（与公司、用户的处理一致）——丢弃会让它的流水变孤儿。
- 流水缺 id / 缺日期仍必须丢弃（无法渲染），但计入 `NORMALIZE_REPAIRS.transactions`，由 `dataQualityIssues()` 报「本次加载有 N 笔流水被跳过」，不再静默。

### 19.4 账套导入预检（pre-apply）
- `flpack:inspect` 在主进程解包后统计并回传 `warnings`：`companiesMissingId` / `accountsMissingId` / `orphanTransactions` / `droppedTransactions`。
- 导入摘要弹窗补「账户数量」一行（`manifest.stats.accounts` 早已存在但从未渲染），并在有 warning 时用 `.warn` 列出，**保留「取消」**——用户可在造成损失前中止。

### 19.5 移除 `flpack` 的 `new` 模式分支
- `applyImport()` 里 `opts.mode === 'new'` 的「追加为新账套」分支：从未接入 UI（`opts.mode` 全仓只在该行出现，`main.js` 缺省 `overwrite`），且给主键加后缀后**没有重写** `accountId` / `categoryId` 等引用字段，缺 id 的实体会撞成同一个 `"undefined_imp<ts>"`。
- 处理：整段删除，`main.js` 不再透传 `mode`。只保留「覆盖导入」。
