# 这次开发的心路历程

**项目**：合资金账 FundMerge v4.9.2 → v5.0.0
**周期**：2026-10-28 ～ 10-29（两个工作日）
**规模**：24 条需求、5 个渲染层脚本、约 1.2 万行前端代码、3 个缺陷、174 例测试

---

## 一、开场：一份看起来很"正常"的需求清单

拿到的是 24 条 Bug，写法很典型——用户视角、现象描述、没有根因。比如「首次使用页面每次都会弹，都需要新增一个账号，逻辑有问题」。

第一反应是：这些大多是 UI 层的小修小补，一两天能完。

**这个判断错了。** 24 条里有 5 条，按原文去改会改错地方：

| 原文说 | 实际是什么 |
|---|---|
| "首次使用页每次弹，逻辑有问题" | 不是判断逻辑错，是 `ensureMasterAccount` 按 `username==='owner'` 找人，而首启页会把账号**改名**——改完名下次启动找不到，就再造一个 |
| "云盘备份页面卡死" | 不是网络慢、不是渲染重，是 `renderView` 里 `versions().then(renderView)` 的**无限递归**。`versions()` 读本地索引，1ms 返回，于是 1 秒内自我重绘上千次 |
| "趋势只能看近 30 天" | 按钮**渲染了但没接事件**。`data-action="trend-range"` 在 app.js 里根本没有 case |
| "往来账款净额显示数据错误" | 下钻页读 `companyTotals().receivable`，**这个字段从来不存在** → 恒为 NaN |
| "编辑没有二次确认" | 确认组件 `confirmDialog({requireCode})` 早就写好了，19 处都在用，只是编辑流水没接 |

这件事给了第一个教训：**用户描述的是症状，不是病灶**。把症状当病灶改，改完症状还在。

## 二、第一批：三个 P0，一个比一个藏得深

### 云盘卡死

最戏剧性的一个。表面看是"页面卡死"，实际是一行代码：

```js
case 'backup': html = viewBackup(); loadBackupCfg();
  window.desktop.backup.versions().then(list => { UI.backupVersions = list; renderView(); });
```

`renderView` → 取版本 → 再 `renderView` → 再取版本。因为 `versions()` 读的是本地索引文件，几乎是同步返回的，这个循环跑得飞快，主线程被 DOM 重建打满，点什么都没反应。

修法不是加 `debounce`，而是**切断回路**：数据取回来只更新 `#bk-versions` 这一个容器，不重绘整页。顺带解决了"重绘会把用户正在输入的 WebDAV 密码冲掉"这个隐性毛病。

### 集团净额 NaN

`companyTotals` 只返回 `{total, cash, bank}`，而 `drillRows('net')` 去读 `t.receivable` 和 `t.payable`。`undefined - undefined = NaN`，一路带到卡片、进度条宽度、排序比较。

有意思的是**卡片上的数字是对的**（它用的是 `groupTotals`，那个函数算了 receivable），只有点进去的下钻页是 NaN。所以用户看到的是"数字对，但点开全是 NaN"——这种"一半对一半错"的 bug 最容易被当成"显示问题"糊过去。

### 集团总公司

这条最费脑子。用户说"集团作为独立公司使用时，无法修改和查看任何数据"。

第一反应是权限问题。查了半天权限代码，没有锁。

真相是三个口径 bug 叠加：
1. `accountingCompanies()` 在 registry 模式下把总公司剔出合并
2. 但明细列表仍用 `DB.companies`（含总公司）→ **列表里有、合计里没有**，看起来像"数据丢了"
3. 而 `accountingCompanies()` 还有个兜底 `list.length ? list : DB.companies`——只有总公司一家时静默回落成"全部公司"，把"没有成员"伪装成"全部合并"

最后那个兜底是最阴的：它让错误状态**看起来正常**。删掉兜底、改成返回空集 + 引导页，反而暴露了真实问题。

## 三、第二批：那些"按钮是死的"的地方

做穿透的时候发现一个规律：**很多"功能缺失"其实是"没接事件"**。

- `trend-range` 没有 case
- `data-report` 没有监听（统计汇总页的日期筛选输进去完全无效）
- `drill-open` 不写 `txFilter`（点"查看明细"进去看到的是全部流水，对不上数）

这类问题的共同点：**渲染层写完了，事件层漏了**。因为渲染是"看得见"的，事件是"看不见"的，测试时点一下就知道，但没人点。

所以后来给自己定了个规矩：凡是加了 `data-action`，必须同时在 app.js 里搜一遍有没有对应的 case。这个检查很土，但有效。

## 四、多币种：一次差点写错的技术选择

多币种的方案讨论了很久（账户级 / 流水级 / 账套级）。最后选账户级，理由是改动面可控。

真正的坑在实现时：

```js
// 看起来最自然的写法
function companyBalanceAt(co, upto) {
  return co.accounts.reduce((s, a) => s + toBase(balanceOf(a, upto, co), accCurrency(a)), 0);
}
```

**这个写法会卡死。** `balanceOf` 每次遍历全部流水，账户数 × 流水数 = O(n×m)。而 `groupSeries` 要算 200 个点，30,000 笔流水 × 5 个账户 × 200 点 = 3000 万次运算。

改成**单遍扫描 + 按币种分桶**：

```js
const buckets = {};           // 币种 → 金额
for (const t of co.transactions) {
  if (t.noCash) continue;
  buckets[accCur.get(t.accountId)] += (t.type === 'in' ? +1 : -1) * t.amount;
}
// 最后每个桶乘一次汇率
```

O(n)，而且顺手把 `noCash` 双算的问题一起解决了——因为代付镜像的 `accountId` 是空字符串，天然进不了桶。

**这次学到的**：性能问题往往不是"代码写得丑"，是"复杂度选错了"。同一段逻辑，换个数据结构就从 O(n×m) 变 O(n)。

## 五、测试：三次"打脸"

### 第一次：129 例，1 失败——是我错了

跑完第一版测试，129 例 128 通过。唯一失败的是「撤销一次核销后剩余 2000」。

查了半天代码，发现**产品是对的，我的期望值写错了**：撤销第二次核销后，应该回到第一次之后的状态（剩 3000），我写成了 2000。

教训：**测试也会骗人**。失败时先怀疑测试，再怀疑产品——但反过来，如果测试全绿就以为产品没问题，那更危险。

### 第二次：DEF-01，自己挖的坑埋了自己

写导入测试时顺手加了一条「非法结构被拒绝」，结果发现：**合法结构也被拒绝了**。

`applyImport` 的校验还停留在 v2 单公司时代：

```js
if (!data || !Array.isArray(data.accounts) || !Array.isArray(data.transactions)) throw ...
```

而 v3 导出的结构是 `{ companies: [...] }`，顶层根本没有 `accounts`。

也就是说：**用户按提示导出备份，一旦需要恢复，恢复不了。** 备份功能等于摆设。

这是整个项目最严重的一个 bug，而且是我自己在做「多公司」重构时留下的——改数据模型时只改了导出，忘了改导入的校验。

更糟的是，即使放行，后面还有第二个雷：统计读的是 `next.accounts`，而那是**代理属性**，此时还指向旧的 `DB`，显示的数字是错的。

### 第三次：DEF-02，我"声称修了"其实没修

上一轮我信誓旦旦地说「项目笔数虚高已修」。这轮加了个专项用例，一跑：**还是 2 笔，不是 1 笔**。

回去看代码：

```js
(co.transactions || []).forEach(t => {
  if (t.projectId !== projectId) return;
  count++;                                    // ← 这里，转账也计数
  if (t.type === 'out') out += txBase(t, co); // ← 我只改了金额分支
});
```

我改了金额的计算，没改 `count++` 的位置。**记忆里的"已修"和代码里的"未修"不是一回事。**

这件事的教训比 bug 本身重要：**"改了"必须能被用例证明，不能靠回忆**。所以后来每个修复都配一条断言，跑绿了才算完。

### 顺带：DEF-03，一个 null 能让软件起不来

模糊测试喂了 20 组畸形数据，三组直接崩：

- `{users:[null]}` → `u.security` 读 null
- `{companies:[{debts:[null]}]}` → `x.type` 读 null
- `{companies:[null,1,'a']}` → 全被过滤后 `companies[0].id` 读 undefined

这意味着**一个损坏的备份文件就能让软件启动失败**，而且没有任何提示。

修法很朴素：加个 `objs()` 过滤器，把数组里的非对象全洗掉；公司列表为空时兜底建一家。

**边界数据比正常数据更能暴露问题**——正常流程跑一百遍，不如喂一个 null。

## 六、环境的坑：那些和代码无关的挫败

### 构建永远 EPERM

`electron-builder` 解包后要把 `win-unpacked.tmp` 改名成 `win-unpacked`，每次都失败：

```
EPERM: operation not permitted, rename ... 
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]
```

原因：工作区内新生成的 `resources/app.asar` 会立刻被快照服务独占，文件被锁着就改不了名。

解法：**把工程复制到临时目录构建**，用目录联接指回 `node_modules`，构建完再把产物拷回来。听起来绕，但一次配好之后每轮构建都省心。

### 一堆小坑

- `cmd /c mklink` 被安全策略拦，只能用 PowerShell 的目录联接
- `Copy-Item -LiteralPath "$src\assets\*"` 不展开通配符（`-LiteralPath` 就是字面量），必须用 `-Path`。我因此白白构建了一次旧代码
- 隐藏窗口 `setSize` 不生效，自适应测试三次测的都是同一个宽度（1267），必须 `setBounds` + `showInactive`
- 在 bash heredoc 里写 PowerShell 命令会被安全策略判定为"绕过"，得换写法

这些都不难，但每一个都会让你以为"代码有问题"，实际是工具在跟你作对。**区分"我的 bug"和"环境的脾气"，能省掉一半的自我怀疑。**

## 七、交付：最后一公里也不轻松

打包本身不复杂，麻烦的是细节一致性：

- 版本号三处同改（`package.json`、`APP_VERSION`、`artifactName`），漏一处就会出现"装完显示旧版本"
- `FundMerge-打包工程/` 必须逐文件同步，否则重建出来是旧的
- 内置手册 `assets/manual.html` 和交付的 `操作手册.html` 是同一份，改了文档不重建包，装出来的软件里还是旧手册
- LFS 推 280MB，等了 9 分钟

这次交付还犯了两个小错：第一次 `git add -A` 把历史测试报告删了（因为新目录里没拷），发现后用 `git restore --source=HEAD~1` 捞回来；`收尾交付说明.md` 和 `操作手册.html` 一开始忘了更新，是用户追问才补的。

**交付清单应该倒着写**：先列出"必须更新的文件"，再逐项打勾，而不是做完想起什么补什么。

## 八、回头看，哪些做对了

1. **先摸根因再动手**。三个 P0 里有两个，如果按原文改，改完还是坏的。
2. **测试用例跟着修复走**。每个缺陷修完立刻补一条断言，防止"以为修了"。
3. **口径问题当成一等公民**。`noCash`、`accountingCompanies`、`currency` 这些看起来是"实现细节"，实际决定了所有数字对不对。
4. **把"看不见的东西"写进文档**。`noCash` 分两类口径、`companyBalanceAt` 不能逐账户算、代理属性会指向旧 DB——这些坑不写下来，下一个人一定再踩一遍。

---

## 九、哪些还能做得更好

1. **测试启动太晚**。如果第一天就搭好自动化骨架，DEF-01 那种"备份导不回来"的问题在开发阶段就会暴露，而不是等到全量测试。
2. **文档更新没有清单**。靠记忆更新文档，必然漏。应该有一份 `交付前必改清单`。
3. **视觉验证缺失**。自动化只看 DOM 文本，布局错位、文字重叠完全测不到，这部分仍然靠人眼。
4. **没做真机安装验证**。静默安装在当前环境跑不通，只能留给人工——这属于"没做完"，不是"不需要做"。

## 十、一句话总结

这活儿的难点不在写代码，在**判断哪句话是真的**：用户说的是症状、注释说的是旧逻辑、我的记忆说的是"已经改过"。

三次打脸（期望值写错、自己挖的坑、声称修了没修）都指向同一件事——**只有跑起来的用例不会撒谎**。
