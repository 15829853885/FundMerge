## 构想与选型

### 最初设计
【事实】v1.0 = 单公司资金流水 + 账户余额。数据模型最早只有"账户 + 流水"。【推断】没有一开始就想做集团/多币种/云盘，这些是后面逐版长出来的。

### 核心使用场景
【事实】从功能倒推：日常记账（收入/支出/内部转账）、看余额、出报表、管往来款、做预算、管多公司并出集团合并口径、换电脑能整套搬走、云盘自动备份。【推断】核心用户就是你自己（和可能一起做账的家人/员工），不是对外销售的产品。

### 技术选型及考虑
【事实】从《开发交接说明》和代码看：
- Electron 打包成 Windows 桌面软件（exe 安装版 + 免安装解压版）；
- 前端零框架零构建：五个脚本顺序加载（core.js / ui.js / views.js / modals.js / app.js，另有 scene.js 做 three.js 3D 氛围层），不引 ES module；
- 数据落本地 `data/data.json` + `files/` 附件目录，不联网不上传；
- 密码用 PBKDF2-SHA256 加盐哈希，云盘凭据用 Electron safeStorage 加密，账套包用 PBKDF2(120k)+AES-256-GCM；
- 渲染层用 `data-action` 事件委托统一分发。

【推断】选 Electron + 原生 JS 而不是 Web 框架，是因为自用、要离线、要打包成桌面程序，追求简单可控。【待回忆】为什么没用现成框架（React/Vue）或现成记账软件，材料里没有明确说。

### 放弃的方案
【事实】多币种方案讨论过"账户级 / 流水级 / 账套级"，最后选了账户级，理由是改动面可控（心路历程原文）。【待回忆】其它被放弃的方案（比如早期的数据存储选型）材料里没写。

### 原型 / 草图
【待回忆】材料里没有早期原型或草图的记录。
