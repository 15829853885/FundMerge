# 合资金账 FundMerge · 打包与发布说明

> 适用版本：v5.2.0 ｜ 更新：2026-10-30
> 本文说明如何从源码生成 Windows 安装包，以及发布前必须通过的检查。

> **目录位置（v5.2.0 起）**：交付目录改名为 `FundMerge/`，只保留 `01-安装版`、`02-免安装版`、`03-网页版`、`04-文档` 四类；
> 打包工程 `FundMerge-打包工程/` 位于工程根目录（不再放在交付目录的 `04-文档` 下），构建产物不入库。

## 一、环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11 64 位（构建机） |
| Node.js | 20 或 22（建议 22 LTS） |
| npm | 随 Node 附带 |
| 磁盘 | ≥ 2GB 空闲（node_modules + 构建产物） |
| 网络 | **仅构建时需要**（下载 Electron 二进制）；运行时完全离线 |

## 二、首次准备

```bash
cd FundMerge-打包工程
npm install
```

`npm install` 会下载 Electron 45 的 Windows 二进制（约 110MB）。国内网络建议设镜像：

```bash
set ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
npm install
```

## 三、构建安装包

```bash
npm run dist
```

等价于：

```bash
electron-builder --win --x64 --config.directories.output=dist
```

**产物**：

```
dist/
├─ FundMerge-Setup-<version>.exe        安装包（约 116MB）
├─ FundMerge-Setup-<version>.exe.blockmap
└─ win-unpacked/                        免安装目录（可直接运行 合资金账.exe）
```

## 四、版本号怎么改

需要同时改 **三处**，缺一不可：

| 文件 | 字段 | 说明 |
|---|---|---|
| `package.json` | `version` | 决定安装包文件名与 asar 内版本 |
| `assets/core.js` | `const APP_VERSION = 'x.y.z'` | 界面「关于」显示 |
| `package.json` | `build.win.artifactName` | 默认 `FundMerge-Setup-${version}.${ext}`，一般不用改 |

> ⚠️ **electron-builder 的 `build.productName` 与 `build.win.artifactName` 会覆盖顶层同名配置**。
> 只改顶层 `productName` 不生效——这个坑在 v4.0.0 踩过，出来的还是旧名字。

## 五、构建必踩的 5 个坑

1. **先结束 `合资金账.exe` 进程**
   否则解包阶段报 EBUSY。用任务管理器或 `taskkill /F /IM 合资金账.exe`。

2. **输出目录不能有 `win-unpacked.tmp` 残留**
   某些环境的 safe-delete 垫片会把 `fs.rm` 转成"回收站"，大目录 trash 失败 → 报
   `[safe-delete] 操作失败: Error during a trash operation`。
   **规避：换一个新的输出目录名**（如 `dist2`、`dist3`）。

3. **不要用 `mv dist dist_old` 替换产物**
   文件系统视图有延迟时会误删产物。直接 `cp` 安装包到交付目录。

4. **不要用 `&` 后台运行构建**
   父 shell 退出会带走子进程，构建中途被杀。

5. **构建后检查 `win-unpacked` 是否干净**
   如果在里面跑过 exe，会生成 `debug.log`，门禁会拦。

## 六、发布前必跑的门禁

```bash
# 1) 先验尺子本身没被改坏
sh deliverables/pack-gate.sh --self-test
# 期望：exit 0，输出「自检结果: PASS（6 例）」

# 2) 再验产物
sh deliverables/pack-gate.sh dist
# 期望：exit 0，输出「[门禁] PASS（规则 v7 / 指纹 xxxx）」
```

**退出码非 0 = 禁止发布。**

### 6.1 门禁查什么

| 类 | 检查内容 |
|---|---|
| A 结构断言 | 顶层条目白名单；禁止 `data/`、`*.bak.json`、`data-location.txt`、`debug.log`、开发文档 |
| B 文本扫描 | 明文凭据赋值、真实手机号、开发者本机路径（**解包 asar 后扫文本**，二进制 grep 不可靠） |
| C 版本一致性 | asar 内 `package.json` 的 version 必须等于安装包版本 |

### 6.2 一个必须注意的陷阱

```bash
node deliverables/pack-scan.js dist | tail -20 ; echo $?   # ← 拿到的是 tail 的退出码（恒 0）
sh deliverables/pack-gate.sh dist ; echo $?                 # ← 正确，透传 node 的退出码
```

**CI 里用管道接门禁会导致"扫描失败但构建通过"的静默失效。**

### 6.3 门禁的性质（对外表述必须准确）

门禁是 **「自证型（self-attested）」**：执行者与被验证者是同一个人。

- 可以说：「我们建立了发版检查机制」
- **不能**说：「检查已由独立环境执行」

指纹机制防的是**无意改动与夹带改动**，不防**有意绕过**（能改脚本的人同样能改 expected 文件）。
真正防恶意需要：git 历史与签名、分支保护、**CI 从干净 checkout 运行**。

## 七、代码签名（当前未做）

当前**没有配置代码签名证书**，因此：

- 安装时 Windows 会弹「未知发布者 / SmartScreen」警告
- 用户需点「更多信息」→「仍要运行」

**如果要签名**：

1. 购买代码签名证书（OV 或 EV，约 $200–500/年）
2. 在 `package.json` 的 `build.win` 中配置：

```json
"win": {
  "certificateFile": "path/to/cert.pfx",
  "certificatePassword": "环境变量读取，不要写死",
  "signingHashAlgorithms": ["sha256"],
  "rfc3161TimeStampServer": "http://timestamp.digicert.com"
}
```

3. 或用环境变量：`CSC_LINK`（pfx 的 base64 或路径）、`CSC_KEY_PASSWORD`

> EV 证书需要硬件 token，CI 上签名要额外配置。OV 证书首次签名后仍需一段时间积累 SmartScreen 信誉。

## 八、安装包行为说明

| 项 | 当前配置 |
|---|---|
| 安装方式 | 非一键（`oneClick: false`），用户可选安装目录 |
| 安装范围 | 当前用户（`perMachine: false`），**不需要管理员权限** |
| 桌面/开始菜单快捷方式 | 创建，名称为「合资金账」 |
| 安装后自动运行 | 是（`runAfterFinish: true`） |
| 卸载是否删数据 | **否**。`build/installer.nsh` 的 `customRemoveFiles` 会把 `data` 目录移出再移回 |
| 安装根目录附带文档 | `操作手册.html`、`开发交接说明.md`、`需求解读与实施方案.md`、`打包与发布说明.md`、`icon.png` |

### 8.1 卸载/升级保留数据的实现

electron-builder 默认卸载脚本执行 `RMDir /r $INSTDIR`，而本产品把账本放在 `<安装目录>\data`，
**覆盖安装（先跑旧卸载器）会连账本一起删掉**。

`build/installer.nsh` 的 `customRemoveFiles` 宏处理三个窗口：

1. `$TEMP` 里上次升级的残留 → 改名保留，不无条件删
2. 数据已移出、尚未移回的间隙断电 → 写 `fm-moving.flag`，`main.js` 的 `recoverInterruptedUpgrade()` 启动时自动搬回
3. 移回失败 → 用复制兜底 + 标记文件

## 九、发布流程清单

```
□ 1. 改版本号（package.json + core.js）
□ 2. 更新文档（操作手册 / 交接说明 / 需求解读）
□ 3. node --check assets/*.js  electron/*.js     全部通过
□ 4. 结束 合资金账.exe 进程
□ 5. 构建到新的输出目录
□ 6. sh deliverables/pack-gate.sh --self-test     exit 0
□ 7. sh deliverables/pack-gate.sh dist            exit 0
□ 8. 干净机器上装一遍，确认：首启设口令 → 登录 → 载入示例 → 20 个页面都能开
□ 9. 覆盖安装验证：装旧版 → 造数据 → 装新版 → 账本还在
□ 10. 记录门禁指纹（pack-gate.expected 内容）到发版记录
□ 11. 分发安装包 + 告知用户「升级前请先导出账套包」
```

## 十、常见问题

**Q：构建报 `[safe-delete] 操作失败`？**
A：输出目录有 `win-unpacked.tmp` 残留。换一个新目录名重新构建。

**Q：安装包文件名还是旧名字？**
A：检查 `build.productName` 与 `build.win.artifactName`，这两个会覆盖顶层配置。

**Q：装完发现里面带了测试数据？**
A：`win-unpacked` 被打包前运行过。重新构建，并跑门禁（会拦 `data/` 与 `debug.log`）。

**Q：用户反馈升级后账本没了？**
A：先让他检查安装目录下是否还有 `data` 文件夹；再检查 `%TEMP%\fm-keep-data` 是否有残留
（安装器中断时数据会停在那里，重新启动软件会自动搬回）。

**Q：如何降级？**
A：**不保证**。数据目录位置没变，但新版本新增字段旧版不识别。降级前必须先导出账套包（JSON 备份不含附件）。

## 附录：v5.0.0 发布要点

### 版本号三处同改

1. package.json 的 version 改为 5.0.0
2. assets/core.js 的 APP_VERSION 改为 5.0.0
3. package.json 的 build.win.artifactName（默认按 productName 与 version 生成，一般无需改）

只改顶层 productName 不生效——v4.0.0 踩过。

### 构建必须在工作区外

electron-builder 解包后要把临时目录改名为 win-unpacked，而工作区内新生成的 resources/app.asar 会被快照服务立刻独占，导致改名报 EPERM。步骤：

1. 把工程复制到系统临时目录，排除 node_modules、dist、dist-v500、.git、.workbuddy-ai
2. 在临时目录里创建指向原工程 node_modules 的目录联接
3. 在临时目录执行 electron-builder
4. 把产物拷回工程目录

两个注意点：创建目录联接不能用 cmd 的 mklink（会被安全策略拦截），要用命令行工具自带的联接子命令；复制时带通配符必须用 -Path 参数，-LiteralPath 不展开通配符。

### 发版门禁

执行 deliverables/pack-gate.sh dist，必须 PASS：结构断言 20 条目、文本扫描 0 告警、asar 与 exe 版本一致。

### 同步 FundMerge-打包工程

该目录用于重建，必须与主工程逐文件一致（assets 下全部脚本、electron 下全部脚本、index.html、package.json），否则重建出来是旧版本。发布前用 MD5 比对一遍。
