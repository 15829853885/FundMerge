## 2. 这一版做了什么

### 2.1 数据正确性（本版重点）

| 问题 | 影响 | 根因 | 修法 |
|---|---|---|---|
| **找不到账户的流水按 1:1 计入合计** | 多币种账套金额静默失真（汇率 > 1 少计、< 1 多计），界面上看不出来 | `txBase` 查不到账户时把币种替换成本位币，`baseRate` 直接返回 1 | 返回 `0`（排除）+ 页面提示「有 N 笔流水找不到所属账户」 |
| **账户缺标识被丢弃** | 账户凭空消失，其流水变孤儿 | `normalize()` 里 `filter(a => a.id)` | 补 `uid('a')`，与公司、用户的处理一致 |
| **流水缺日期被丢弃** | 数据静默消失，无任何提示 | `filter(t => t.id && t.date)` 无计数 | 仍丢弃（无法渲染），但计数并提示 |
| **导入账套无法预知损失** | 覆盖导入后才发现账户/流水没了 | 摘要只显示公司数、流水数 | 新增预检：账户数 + 缺标识账户 / 孤儿流水 / 将被跳过的流水，**保留「取消」** |
| **`flpack` 的 `new` 分支** | 主键加后缀但引用未重写、缺 id 撞车 | 从未接入 UI 的死代码 | 整段删除，只保留「覆盖导入」 |

> 一句话：这版把"算不出来"的流水从「按 1:1 算个错的数」改成「排除并说出来」，与项目既有的「缺汇率绝不静默折算」原则一致。

### 2.2 登录与权限

- **登录身份改下拉**：记账员 → 查看员 → 管理员（管理员固定最后），按账号记忆、首登预置真实身份、手动改过不再被覆盖
- **注册可选用户类型**：仅记账员 / 查看员，非法值阻止提交；管理员仍需管理员创建
- **新增「查看员」只读角色**：可看可导出，不能增删改；写按钮禁用并提示，绕过界面也会被拦截
- **修掉三个权限缺陷**：查看员被静默降级成记账员（还会白得写权限）、自我降权守卫晚于赋值、缺 id 的历史用户无法管理

### 2.3 体验与无障碍

错误提示条加 `role="alert"` 并在出错时滚动、聚焦到字段；认证页控件统一 40px（修掉一条写了却从未生效的 CSS 规则）；22 处嵌套 `<label>` 改合规结构；登录公司下拉在账号未识别前禁用。

## 4. 架构口径（三条硬边界，请勿按「缺陷」提需求）

1. **单机单文件**：数据是一个 `data.json`，全量载入内存。不是数据库，没有事务与并发写保护；多台电脑同时写同一份会互相覆盖，只能靠网盘同步做「轮流使用」。
2. **完全离线**：除云盘备份外不发起任何网络请求；不引 CDN、不引图表库。
3. **金额用浮点 + 两位小数四舍五入**：适合记账展示，不适合做需要严格精度的高频金融计算。

---

## 5. 能力上限（是天花板，不是 bug）

| 项 | 上限 | 原因 |
|---|---|---|
| 流水量 | 建议 ≤ 5 万笔 | 全量载入内存；30,000 笔时全量渲染 335ms，再往上首屏会变慢 |
| 云盘版本池 | 最多 7 个 | 超出自动删最旧 |
| 附件 | 单文件大小受云盘与内存限制 | 打包时全量读入内存 |
| 公司数 | 无硬限制，但集团页按公司逐个汇总 | 数十家以内体验正常 |

## 8. 验收建议路径（约 20 分钟）

1. 安装 → 首次启动，设置管理员账号与两个预留问题
2. 建两个账户（一个 GHS 现金、一个 USD 银行）→ 设置里录 USD 汇率
3. 记 3 笔流水（收入 / 支出 / 跨币种转账）→ 看账户余额与「资金总额」是否对得上
4. 登录页：切「查看员」登录 → 确认写按钮是灰的、点击有提示；再切回管理员
5. 注册页：不选「注册用户类型」直接提交 → 应提示错误且不建号
6. 建 1 笔借支 → 核销一半 → 再核销剩余 → 撤销一次
7. 报表 → 资金对账单：五项加总是否等于总账面
8. 集团总览：四个卡片各点一次，明细合计是否与卡片一致
9. 设置 → 导出 JSON → 再导入回来，数据是否完好；再试「导入账套」，看摘要里是否列出账户数
10. 云盘备份：配 WebDAV → 立即备份 → 版本池出现 → 恢复一次
11. 切深色主题 + 拉窄窗口，看有无文字看不清或横向滚动

## 9. 后续演进建议（按性价比）

1. **代码签名**（成本低、体验提升明显）
2. **把关键断言沉淀成仓库里的测试**（现在数据口径那几条还是一次性脚本）
3. **构建后自动校验包内文档版本**（门禁只查 asar/exe 一致，不查文档，本轮因此重打三次包）
4. **附件异步打包**（当前打包在主进程同步执行，附件多时会卡）
5. **数据层换成 SQLite**（彻底解决大数据量与并发写）
