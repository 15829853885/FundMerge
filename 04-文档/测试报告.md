## 二、这一版测什么（范围）

v5.2.0 改了三块，测试也围绕这三块 + 全量回归：

1. **数据正确性**（本轮重点）：找不到账户的流水不再按 1:1 折算、账户缺标识不再丢弃、导入账套前预检、移除 `flpack` 的 `new` 死分支
2. **登录与权限**：登录身份下拉、注册用户类型、查看员只读角色、用户管理的角色保持
3. **回归**：三角色 × 20 个页面渲染、多币种折算、集团代付口径、登录/注册页结构

## 三、本轮用例与结果

### 3.1 数据正确性（孤儿流水与折算）

构造数据：本位币 GHS，USD 账户汇率 12；`t1` = USD 100 正常收款；`t2` = 100 但 `accountId` 指向不存在的账户（孤儿流水）。

| # | 用例 | 期望 | 实测 | 结果 |
|---|---|---|---|---|
| 1 | USD 流水按汇率折算 | `txBase(t1)` = 1200 | 1200 | ✅ |
| 2 | 孤儿流水金额 | `txBase(t2)` = 0（**不是 100**） | 0 | ✅ |
| 3 | 公司资金合计 | `companyBalanceAt` = 1200（不含孤儿） | 1200 | ✅ |
| 4 | 区间统计 | `inflow` = 1200、`outflow` = 0 | 1200 / 0 | ✅ |
| 5 | 数据质量聚合 | `dataQualityIssues()` 报 `orphan-tx: 1` | `[{kind:'orphan-tx',count:1}]` | ✅ |

## 七、复现方式

本轮用例在真实 Electron 渲染进程中执行，关键步骤：

```js
// 1. 起一个静态服务器指向工程根，BrowserWindow 加载 index.html
// 2. 注入数据（本位币 GHS + USD 汇率 12 + 一条孤儿流水）
DB.meta.fx = { base:'GHS', rates:{ USD:[{ date:'2026-01-01', rate:12 }] } };
// 3. 断言
txBase(t1) === 1200;                 // 正常折算
txBase(t2) === 0;                    // 孤儿流水排除
companyBalanceAt(co) === 1200;       // 合计不含孤儿
dataQualityIssues()[0].kind === 'orphan-tx';
// 4. 主进程纯函数
require('./electron/flpack.js').inspectWarnings(ledger);  // 四类计数
```

页面回归：`startSession(role)` → `renderShell()` → 逐个 `UI.view = v; renderView()`，检查 `#view-root` 非空且无 `error` 事件。

## 八、结论

- **数据正确性**：本轮最重的一条（DEF-07）已修。改动后"算不出来"的流水会被**排除并告知**，而不是"按 1:1 算个错的数"。这与项目既有的「缺汇率绝不静默折算」原则一致。
- **权限**：查看员角色从"建得出来但保不住"变成"建得出、保得住、写不了"。
- **回归**：60 次页面渲染、多币种折算、集团口径、登录注册均无退化。
- **仍需人工**：安装向导、视觉走查、真实数据试跑（见第六节与《收尾交付说明》验收路径）。
